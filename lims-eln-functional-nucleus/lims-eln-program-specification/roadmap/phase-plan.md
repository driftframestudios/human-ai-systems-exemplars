# Recommended Chain of Action

The sequence is coordinated through `coordination-horizon.json`. Focus bands can
adapt as evidence arrives while the contractual gates in this plan remain
stable.

## Phase 0 — Reconcile claims and authority

Reconcile repository role, provenance, release state, evidence mode, intended
use, record and signature inventory, representative data profile, recovery
objectives, and accountable owner roles.

## Phase 1 — Release control contracts

Release stable requirements, rules, failure twins, recovery examples, fixtures,
forecasts, bounded operations, Practitioner Probes, proof classes, receipt
contracts, and first-receipt instructions.

Settle the database finding ledger, probability-framed plan set, canonical data
primitive contract, migration and reconciliation contract, database receipt
registry, and digest-bound release manifest.

## Phase 2 — Golden specimen and durable boundary

Carry one representative synthetic specimen through accession, custody,
instrument ingress, scientific review, release, vendor projection, migration,
restore, security, and observability. Implement durable idempotency, transaction,
outbox, inbox, retry, and recovery behavior around that path.

## Phase 3 — Bounded-caller vertical slice

Exercise one authorized read, one narrow idempotent write, and one
approval-gated broad write. Verify strict input validation, caller identity,
tenant and resource scope, budgets, approval binding, effect inventory, audit,
and recovery.

## Phase 4 — Configured vendor qualification

Run the shared conformance suite against LabKey, Benchling, and Sapio while
preserving vendor-specific semantics and version evidence.

## Phase 5 — Migration, rollback, restore, and data exit

Exercise representative volumes, historical exceptions, delta catch-up,
semantic parity, rollback, clean restore, continuity, and neutral-reader
export.

Execute the five-phase tool-neutral evolution contract through the selected
Flyway Community 13.0.0 profile, reuse the end-to-end and parameterized
migration suites, compare all nine reconciliation dimensions, exercise the
seven database release gates, and bind results to the immutable migration
catalog and release manifest.

## Phase 6 — Production controls

Exercise production-bound identity, privacy, telemetry, support, alerting,
fallback, incident response, AWS Parameter Store configuration, Secrets Manager
rotation, KMS context, bounded caches, and redacted retrieval telemetry.

## Phase 7 — Accountable acceptance

Scientific, Quality, Regulatory, Security, Operations, and business owners
record distinct decisions for their bounded scopes.

## Phase 8 — Fully simulated future-reality closure

Select one coherent future version of reality and execute the entire chain
through the simulated-final-state repository. Close all four substantive
receipt classes in `evidence_mode: simulated` with:

- deterministic environment manifests and version bands;
- representative metrics, exceptions, and failure twins;
- evidence artifact locators;
- role-bound synthetic decision records;
- assumptions, falsifiers, limitations, and requalification triggers.

The simulated closure is complete in its own branch of evidence. Each receipt
also preserves a distinct future observed branch whose state begins open.

## Phase 9 — Paired comparison and disconfirmation

Independent review challenges the claims, classifies divergences, preserves
limitations, compares simulated and implementation receipts, and routes
corrections to their owning repository.

## Phase 10 — Settling and promotion

Classify every claim and affordance as verified, designed but unexercised,
simulated, observed, superseded, or exploratory. Promote only contractually
coherent artifacts. Preserve the simulated four-class closure as an executable
comparison baseline and retain the observed successor path as an independent
future evidence opportunity.
