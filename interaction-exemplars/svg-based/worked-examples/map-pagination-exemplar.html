Core pagination and collection traversal

Three complete collection slices use native fragment destinations, distinct maps, and distinct cards. The fragment URL participates in browser history; one responsive pager becomes compact and horizontal on narrow viewports, then becomes a vertical rail when space supports it.

Fragment pagination has a bounded role

The local exemplar preloads 18 records so CSS can exchange complete slices through :target. The production collection uses server-rendered query routes so each response carries one requested slice, its totals, and its current-page semantics.

Final page

Next and Last become boundary text; backward destinations remain links.

Fragment state drives this bounded standalone interaction. Server routes carry the same pagination contract across the full collection.
