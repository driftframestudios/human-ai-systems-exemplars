# Issue and pull-request practice

Load this profile when public or public-possible GitHub prose carries references whose repository or publication standing can change.

## Receiving result

Another collaborator can identify the work by semantic name, understand its decision and evidence, locate every fitting public or repository-local receiver, and continue from those public records. Private Issue numbers and pull-request URLs retain only their authorized lineage role.

## Surface roles

| Surface | Preserve |
| --- | --- |
| Issue body | Outcome, current truth, boundaries, work, completion, and receiving relationship |
| Pull-request description | Material change, scoped evidence, source boundary, and handoff |
| Comment or review | Decision-changing observation, affected surface, remaining condition, and receiver |
| Commit prose | Coherent change identity and durable semantic result |
| Issue-chain receipt | Current front, typed relation, pass condition, next receiver, and release event |

## Practice

1. Pair a same-repository Issue or pull-request number with a semantic title when the number materially aids navigation.
2. Use a relative repository reference only when the receiving collaboration item will remain available to the intended public reader.
3. When repository identity changes, retain the decision locally or form a newly authored public receiver whose contract is current. A current semantic receiver supplies the continuity that a number-preserving placeholder only appears to offer.
4. Replace a gated collaboration link with the durable rationale, changed paths, counts, accepted decision, or local evidence it carried.
5. Keep exact gated collaboration coordinates in the authorized resolver when an authorized return remains useful.
6. Let comments carry transition receipts. Keep the Issue body current when an older option statement would otherwise misroute a new collaborator.
7. Write the final public receipt with semantic work names first; use current public numbers as navigation rather than identity.

## Boundary case

A historical pull request can remain meaningful as evidence while its URL becomes gated. Preserve the reviewed change, source role, content identity, and repository-local artifact. The private resolver retains the exact review coordinate when that lineage still serves an authorized use.

## Profile completion

Every gated collaboration link has become an accepted public receiver, repository-local source, complete local explanation, or stable private-lineage key. The public packet carries zero exact gated collaboration coordinates and names the next receiver through semantic identity and fitting public navigation.
