## Source-policy experiment

One sample performs the ordered raw duration trace 31, 45, 60 at six sessions
on a fresh accepted fixture. Native owner creation, fixture construction and
reset occur outside the sample. Adapter Begin belongs inside the timed trace;
the already-created adapter represents the mounted owner. Model-boundary
wrappers count and time calls. Correctness assertions, byte counting and
summary calculations happen after the clock stops.

- **Direct:** accept all three duration changes; three revisions.
- **Explicit:** retain all three raw values, then Apply once; one revision.
- **Deferred:** queue each raw change through one injected callback, then flush;
  one request and one revision. This measures synchronous policy work; a physical
  frame/task wait is a separate quantity.
- **Preview:** begin and preview, preview all three edits, Apply, then begin and
  preview a fresh draft. This models the preparation policy around the accepted
  UI while leaving DOM work to the browser experiment.

Source policies use the adapter's supported minute-format API. Their final
material fields and cents agree; revision counts intentionally express policy
semantics. The actual browser uses Hours/Minutes and has its own input trace.

Additional source tasks measure complete import and a full-plan replacement
that changes one person's hourly rate from $100 to $101. The latter prices
actual participation fan-out through the existing `replace` command. It is a
source capability observation, ahead of a future team/rate editor.

Each fixture/policy/task gets five sequential runs, 50 warm-up samples and 200
measured samples per run. The order rotates by round. Source policies execute in

## Decision thresholds and summaries

Declare these local engineering targets before observing outcomes:

- Each run's median synchronous fill-action and submit processing is at most **16ms**.
- Each run's empirical p95 processing is at most **50ms**.
- Each run's p95 next-rendering opportunity is at most **100ms**, a scheduling
  diagnostic that is reported independently from processing.

The 16ms target reserves a roughly 60Hz-sized work interval for this simple
control. The 50ms and 100ms values identify tails worth investigating. These are
chosen study budgets, not platform guarantees or field usability thresholds.
A resolution-limited measurement remains explicitly quantized. A failed tail
or unstable cell is reported with all its runs and can trigger a narrowly
scoped follow-up. A noisy/overlapping comparison is **indeterminate**.

Report all five run medians and p95s, their median and full observed range.
The 200 source traces or 50 actions of each type per browser run support descriptive
empirical percentiles only. Events within a run are correlated; five runs remain
five experimental replications. Do not pool them into a larger independent
sample or infer population confidence intervals. Paired policy differences
retain their per-round relationship and operation counts.

If example and medium processing meet the chosen budgets with exact accounting
and stable owned resources, retain full preparation for the next native module.
A caps-only failure narrows the next receiver's capacity claim and earns a
measured scale issue. A current-task failure first identifies the expensive
owner; admission, DOM work and output size remain candidate explanations until
measured separately. A p95 rAF failure alone does not justify incremental math.

## Environment, sequence and recovery

Run Node 22.23.4 then browsers sequentially on one host; an exclusive local
running marker admits one study timing job at a time. Record Node/driver/engine versions, architecture and hardware
class, viewport, operating environment, initial/final load and ordinary desktop
background activity privately. Browser contexts start fresh; warm-up precedes
every measured context. OS caches are warm/uncontrolled. No CPU/network throttle,
privileged cache flush or forced garbage collection is applied.

All raw rows, source archive, absolute paths and private host details stay in
ignored `.local/`. The public report contains neutral fixture/run identities,
source hashes, normalized environment, counts, distributions and decision.
The runner writes each run exclusively and records its attempted start before
work. An interrupted run remains incomplete. Recovery uses a fresh epoch and
retains the complete earlier attempt set; a resumed experiment runs its declared
population again and reports the earlier interruption. A change of host
conditions or source also creates a separate epoch. Report contention and preserve an indeterminate result rather than
selecting only a favorable retry. Finite source and browser populations bound
execution; a failure stops the affected experiment with its completed runs intact.

Independent review checks protocol-to-runner agreement, fixture arithmetic,
actual event capture, timing boundaries, lifecycle ownership and sanitized
summary provenance. Research PR integration and publication keep their existing
human authority.

  presentation latency; the study's synchronous spans retain the narrower claim.

  defines callback scheduling, which supplies an opportunity rather than proof
  that a changed amount has been painted.
