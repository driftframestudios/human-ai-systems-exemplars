# Support Matrix & Stateful Pads

Compare the work behind a plan through named rows, meaningful columns and pads
that open the corresponding detail. People, sessions, support and observations
keep distinct meanings even when they share a compact rack treatment.

**Standing:** review candidate `0.1.0`; ID `vfc:support-matrix-stateful-pads`;
dev receiving contract revised 8 November 2026 for
[#836](https://github.com/driftframestudios/human-ai-systems-exemplars/issues/836).
Palette and shared controls inherit [Studio Rack Composition](README.md).
`main` remains the approved reference until a human cues dev promotion.

## Current compositions

| Surface | Comparison and interaction |
| --- | --- |

Its pale editorial overview sits below the local header; native choice pads fill compact paired modules. |

A recessed people-by-session arranger combines participation with each person's rates, available time, saved edits and local settings. The contribution/session matrix opens Work and Receiver and decision controls while preserving stored responsibility values. |

| Change and Quality | Compact track matrices select a component or quality concept; neighboring work lanes provide its support context. Quality's dark housing and clear pressed pads are the preferred aesthetic precedent for new selection matrices. |

| Funding and Status | Named large radio pads place the selection control at the top left, beside a short label and hint. Persistent pressed state carries the choice. |

Use a matrix when named row/column relationships help a visitor compare. A short
pad rail fits a small choice set. A phase or period lane groups work by that
named scope; moving a pad preserves its identity and relationship meaning.

## State and operation

| Meaning | Visible and semantic reading |
| --- | --- |
| Selected for inspection | Pressed choice identifies the record; expanded state reports its visible receiver. |
| Included in a proposal | Native checkbox or named toggle expresses inclusion. The proposal's Apply boundary remains clear. |
| Included in accepted work | The accepted projection supplies the state. Team planning and People team membership changes update it directly. |
| Person participating | The named person/session checkbox accepts participation directly. The final included person stays visibly selected and disabled, with a concise instruction to add another person first. |
| Linked support | Shared sessions · Handoffs and the selected People contribution use native checkboxes to accept session support directly. Abilities retains its support proposal boundary. |
| Support to choose | Concise empty-state wording opens the corresponding local controls. |
| Outside a card's definition | Not specified preserves the authored definition's scope. |
| Recorded observation | Reviewer, context and revision distinguish the observation from an authored example. |

Color, border and depth reinforce the control's semantic and written state.
Selected Team planning membership uses the current sequencer face: dark green,
signal border and a signal inset; available pads use the resting face and dashed
border. A native checkbox retains the membership operation. Change and Quality
keep their intentionally different fader treatments.

Change's Raise, Reduce, Eliminate and Create keys borrow Quality's compact rail
face: paper at rest, signal color and inset depth for the open action. Each native
button names its shared receiver with `aria-controls`; `aria-expanded` follows
the actual receiver and clears when it closes. One action keeps the active face
even when a small framework maps more than one action to the same component.
Stable keyed buttons retain focus through selection and projection updates.
These keys inspect the current proposal; selection leaves accepted plan history
unchanged. The four-key row becomes two columns at ordinary phone widths.

The selected Change component opens one dark, attached receiver beneath its
initiating board or matrix. This compact receiver supersedes the nested component
and support disclosures. The shared rack header names Change components as the
return owner, the current component or supporting session, Apply and Close. The
shared rack arrival effect follows the Studio motion preference. Its
Support / Methods / Session rail displays one mounted view at a time; Session
appears while a work proposal exists. Switching views retains pending entries.
Pressing the initiating key again, Close or the owner return closes locally and
returns focus to that key, including its replacement after a projection refresh.
The component's pressed face follows the receiver's visibility.

Support places status, sessions and abilities in small recessed modules. Methods
uses stable selection pads and one chocolate explanation panel, with an optional
example. A supporting session uses the approved shared duration module beside
people and funding on wide surfaces; ordinary phone widths retain a readable
single-column arrangement. Local framing may compress spacing, while duration
dial faces, pointers, Hours/Minutes colors and stepper layout stay shared-owned.
Native checkboxes and radios retain their intrinsic control sizes. The receiver's
Apply delegates to the same canonical bottom action and retains top-action focus;
settings and proposed work still enter accepted history together. Closing merely
changes the visible receiver and leaves those draft entries available.

## Creation, assignment and recovery

Named creation regions state the object and scope they add. A plus inside an
existing plan's temporal track appends a working session to that plan and retains
its earlier placements. The horizon's period lanes and New plan row create
distinct records and retain the All plans view. Shelf New plan deliberately loads
its new cassette. Shared sessions creation uses accepted-person context; its
existing person/session cells change participation directly. This differs from the temporal meaning of a session track’s empty cell. Shared sessions maintains its own selected view and local return.

People's Add person, Add team and Add contribution accept useful records with
editing closed. Named ghost creation slots occupy the end of their collections;
hover/focus reveals the plus and touch keeps it visible. A new contribution starts
as Draft artifacts with receiver and decision owner unassigned. Selecting the
record opens its local editor. Role mix stays visible: eight named facet pads
show current values and select one native choice. Bounded role/contribution
choices and team/support membership accept directly; typed person settings keep
Apply and their retained draft. Receiver and decision owner remain independent
selections; team membership supplies neither authority.

The People arranger uses person row headers and working-session column headers.
Native participation pads accept the selected relationship directly and retain
the row's rate, funded/remaining time, team membership and review cues. A session
keeps at least one participant; the affected pad explains that boundary locally.
Selecting a person opens the compact settings receiver beside its role choices;
All people returns to the matrix. Typed settings keep their existing Apply
boundary while direct participation enters the shared Undo history.

Team keys fill their editorial lane and show the parent's name and open state.
Selecting the same key again closes its editor. Move and Remove controls form
one bottom row. Settings pair the short name/membership module with its draft
investment reading at laptop widths, stacking within an ordinary phone width.

Abilities can add a person, team or supporting session from the selected
module, then select it in the current proposal. Creation enters accepted history;
Apply accepts its support assignment. Cancel restores the prior assignment while
the newly created record remains available. The stable amp Undo uses that same
history, independently of cassette selection. Top Apply beside Close delegates
to the same canonical bottom action, with matching label, disabled state,
validation and return focus. The existing bottom row remains available.

The Abilities People receiver pairs team and participation with decision owner
and lifecycle. These groups sit beside each other at laptop widths and stack
at phone widths. Outcome pairs the editable use context with a chocolate
observation prompt. Supporting work pairs existing session choices with a small
new-session module when selected. The same shared ghost creation control supplies
a named, persistent entry beside those bounded choices. Native switch and radio
geometry remains independent of text-field sizing. Selecting another section
keeps its earlier raw entries; Close returns to the selected catalogue key with
that proposal retained.

Each existing person and team choice offers a compact, underlined Rename action
outside its selection label. One short name field opens below that choice group,
with Save name and a shadow-free Cancel. Enter saves; Escape returns focus to
Rename. Empty names receive local feedback. Save updates the canonical name
throughout the plan while stable IDs preserve its relationships; the current
support proposal retains its exact entries and separate Apply boundary. Global
amp Undo restores the shared name and keeps that proposal available for review.
The name field follows the same dark rack and chocolate companion treatment;
native membership switches and decision-owner radio buttons keep their own jobs.

Membership toggles keep available cards mounted in place. Move up/down changes
ordered IDs explicitly, with the shared keyed transition and focus on the moved
person. People team lanes, arranger row order and contribution supporting-work order
use the same keyed movement. The visible Move controls name their direction;
team order expresses arrangement rather than a sequential workflow. Handoff
supporting-work order uses the same keyed movement. The selected people currently receive the full session duration for
every occurrence. A percentage fader remains scoped in
[#798](https://github.com/driftframestudios/human-ai-systems-exemplars/issues/798).
The [inspection contract](contextual-inspection-recovery.md) owns local Close,
Cancel, saved drafts and return behavior.

## Reading and motion

Native tables retain captions and scoped row/column headers. A meaningful cell
remains readable with its row and column. Ordinary phone widths use a named local
scroll region. People places its creation slots after the last record within
that same scrollable collection, with the module heading outside it.
Long labels wrap and headers contrast against their actual background. The pale
Sessions to place tray uses dark text; dark rack captions retain light text. Shape,
text and focus styling preserve state in forced colors.
Abilities catalogue keys use explicit dark text on their pale blue faces;
their selected mint faces retain it. Its shared header's light Close and owner
controls sit on the dark rack housing. Hidden support receivers stay hidden
through responsive layout changes.

Reels and faders may rearrange keyed pads into an authored configuration. Stable
identity carries the movement, and the shared motion preference governs it.
The resulting state is readable independently of animation. Several support pads
can refer to one session; the shared session keeps one cost account.

The [recorded instrument research](../../collaboration/native-investment-studio/usability-research.md#digital-instrument-composition--5-november-2026)
uses the [Push manual](https://www.ableton.com/en/push/manual/) as a precedent for
separating selection from parameter editing. Native table semantics and the
Studio model establish these actual relationships. The precedent supplies an
interaction analogy; human walkthrough evaluates whether it helps this visitor.
