## Purpose and target

Use the selected investment method to prepare a reviewable decision input from named sources, owned assumptions, and deterministic calculations.

- Selected model: Activity-Based Cost-Driver (`model/activity-based.v0.1`)
- Decision question: What does the work cost per sample, assay, site, review, or other driver — and how does that change with scale?
- Human receiver: Open — name the sponsor and accountable finance or operating owner who can authorize inputs and consequences.

## Relevant context and inputs

- Model fit: Use when leadership thinks in throughput and unit economics, or when a project total hides the activity that actually consumes resources.
- Source record: Costing Plan · Activity-Based Cost-Driver (Unit Economics) (`cbaee20c-7507-4425-b5cd-a37adb206749`)
- Shared scenario: Discovery &amp; Alignment (`scenario/discovery-alignment.v0.1`); horizon 3 quarters; complexity connected.
- Scenario scale: `4` staffed people; `30` activity tasks; `3` recovery events; `3` named unknowns.
- Evidence posture: Sample current Initiative Costing state; no claimed FMI economics.

### Method

1. Name the driver events that consume resources.
2. Separate fixed platform, build, and validation cost from variable labor, storage, and support.
3. Trace each approved cost line to a driver and denominator.
4. Compute current and target-volume unit cost, then inspect scale effects.
5. Express value through a changed unit cost and its operating mechanism.

### Inputs

- Driver-event counts
- Approved fixed and variable cost lines
- Current and target volumes
- Review effort and loaded rates
- Assumption register

### Expected outputs

- Cost-driver register
- Current unit cost
- Target-volume unit cost
- Scale sensitivity
- Reserved-input list

## Working state

- Current focus: Throughput, denominator quality, and fixed-versus-variable behavior
- Decision route: 1. Throughput question → 2. Cost-driver register → 3. Deterministic unit cost → 4. Scale reading
- Deterministic operation: Cost allocated to a driver divided by approved driver-event volume
- Inputs still needed: Local driver counts, allocation rules, approved cost lines, and target-volume assumptions
- Next handoff: Benefit Realization when unit-cost change needs a value mechanism; Whole-Life TCO when scale changes recurring run cost

### Work held by people

- Choose meaningful drivers
- Authorize fixed/variable allocation
- Interpret operating consequences

### Work suited to generative AI

- Draft a driver taxonomy from supplied work
- Reconcile terminology
- Surface missing denominators and review questions

### Work suited to deterministic computation

- Allocate approved costs
- Divide by event counts
- Recompute scale scenarios

Tooling fit: A spreadsheet or small data model holds drivers and denominators; a repeatable script recomputes scenarios; an AI collaborator helps structure and challenge the register while a named owner approves every input.

- Evidence and authority boundary: Approved denominators and local cost lines establish the unit reading. Reserved economics stay visibly reserved; a high unit cost is a decision-bearing result.
- Scenario standing: Sample current Initiative Costing state; no claimed FMI economics.

## Requested return

Using the Discovery &amp; Alignment scenario, draft a cost-driver register for this initiative.

Separate fixed and variable work. For each proposed driver, name the numerator, denominator, source, owner, and missing input. Ask for every missing denominator. Keep unavailable economics, rates, volumes, and savings as &lt;reserved&gt; until a named owner supplies and approves them. Return a table plus three scale-sensitivity questions for human review.

Return with this handback:

1. Name the inputs received and the inputs that remain reserved.
2. Keep each source and accountable owner visible beside the value or assumption they supply.
3. Return the requested model output and the smallest questions that move open material toward human review.
