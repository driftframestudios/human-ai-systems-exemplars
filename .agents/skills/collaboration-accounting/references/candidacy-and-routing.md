# Skill candidacy and routing

## Purpose

This reference supports the uncommon branch where immediate route fit remains unclear or a larger collaboration corpus may materially change the decision. The everyday skill path stays in `SKILL.md`.

## Probability referent

The default planning question is:

> What is the probability that this route improves the next materially similar collaboration while preserving proportionate attention cost?

The range concerns route fit. It does not estimate personal preference, universal skill effectiveness, or the probability that a skill will remain permanently useful.

## Route surface

| Route | Strong-fit evidence | Smallest action | Return condition |
| --- | --- | --- | --- |
| `create_now` | Distinct transferable job; no active owner; live or near receiving use; inexpensive revision; explicit trust or keystone consequence | Create one instruction-first skill with a contract, clear trigger, and observable completion | First natural use or a near-miss reveals routing or workflow friction |
| `iterate_now` | Existing owner; observed friction or missing instruction; decision effect is clear; another use is near | Apply the narrowest description, rule, scenario, or reference change that would alter the next use | Next materially similar use tests the changed behavior |
| `queue_with_trigger` | Durable cognitive contract; plausible transfer; receiving use or scope remains unformed | Name the candidate, likely job, evidence, forge condition, and issue or planning address | A real task supplies the receiving job or distinct trigger territory |
| `observe` | Potentially reusable signal; consequence or transfer remains unclear; immediate artifact would add more attention than capability | Preserve one compact observation only when it has a future decision consequence | Recurrence, counterexample, or a live receiving use changes the route |
| `settle_or_fold` | Current result works; new pass repeats evidence; remaining uncertainty lies beyond the current consequence horizon | State the settled effect and one re-entry trigger; return to material work | New evidence or changed intent can alter the decision |
| `merge_or_retire` | Two skills share the same receiving result and triggers, or a skill has lost every realistic receiving use | Preserve useful rules in the clearer owner, record lineage in Git or threadkeeping, and remove duplicate routing territory through normal review | A later task exposes a genuinely distinct job that warrants re-formation |

## Candidacy dimensions

The route becomes clearer when each dimension is read independently:

- **Recurrence:** first recognition, repeated local use, or cross-context recurrence.
- **Consequence:** whether the observation changes a material decision, prevents rework, or creates a new useful capability.
- **Opportunity capture:** whether durable form keeps a valuable future option, connection, or receiver findable.
- **Experimentation cost:** whether prior decisions, artifacts, comparisons, or boundaries materially reduce rediscovery in the next attempt.
- **Expectation negotiation:** whether scope, authority, evidence, completion, or resting conditions become easier to discuss before different assumptions harden.
- **Imminence:** active receiving use, prepared next use, or resting future possibility.
- **Transferability:** usefulness across teams, artifacts, platforms, or repositories without constructing a collaborator profile.
- **Reversibility:** cost of creating, revising, merging, or retiring the instruction-first artifact.
- **Instruction yield:** the concrete future behavior that becomes easier or more reliable.
- **Evidence independence:** observed behavior, external source, human correction, or a self-generated restatement.
- **Recursion pressure:** whether further stewardship displaces the material work that supplies meaningful evidence.

An explicit human declaration can establish trust, authority, or desired experiment posture. It does not erase repository scope, publication boundaries, or material external consequences.

These three contribution dimensions can earn persistence before they earn an independently routed skill. A collaboration account or billet is sufficient when the value is real and an existing contract still owns the receiving job. Formation follows when the job, trigger territory, receiver, and completion become distinct. Recurrence remains routing telemetry rather than an automatic promotion gate.

## Optional starting bands

Ordinal language often carries enough information. When numerical comparison would materially aid a route decision, these broad bands provide verbalized planning priors. They make assumptions discussable and remain revisable after natural use.

| Route | Starting fit band | Typical basis |
| --- | ---: | --- |
| `create_now` | 0.70–0.95 | Explicit experimentation trust, keystone affordance, distinct job, live use, and reversible first version |
| `iterate_now` | 0.70–0.90 | Existing owner, observed friction, clear instruction delta, and near reuse |
| `queue_with_trigger` | 0.55–0.80 | Transferable contract with a plausible future use and an incomplete receiving shape |
| `observe` | 0.50–0.75 | Meaningful but isolated signal whose consequence or transfer remains unclear |
| `settle_or_fold` | 0.75–0.95 | Intended effect holds and another pass brings no decision-relevant state change |
| `merge_or_retire` | 0.60–0.85 | Verified trigger overlap, lineage preserved, and a clearer receiving owner exists |

The ranges never add into a distribution because several routes may remain plausible at once. The selected route follows the strongest combination of receiving use, consequence, evidence, and attention economy.

## Statistical-fit boundary

A statistical-fit claim needs:

1. a stable outcome definition;
2. comparable natural-use observations;
3. an explicit population and horizon;
4. a named method;
5. enough independent observations for the method;
6. calibration or error reporting appropriate to that method.

Until those conditions exist, probability bands remain attributed planning priors. Collaboration accounts provide qualitative field evidence rather than a hidden dataset or performance score.

## Reversible lifecycle vocabulary

The lifecycle uses plain operator-blind identifiers and allows ecological language to remain visible as a human-facing interpretation. The named probability object is:

> **P(vocabulary-hold):** probability that the lifecycle vocabulary remains legible to a cold human or AI collaborator, avoids common technical collisions, and remains expressive through the next two materially different skill cycles.

| Candidate vocabulary | Generated design prior | Useful quality | Main limitation |
| --- | ---: | --- | --- |
| Plain operational language throughout | 0.34 | Highest immediate legibility | Common words can collide with workflow and package vocabulary |
| Literary language throughout | 0.06 | Memorable and temporally expressive | Publishing and musical senses weaken named-entity recognition |
| Ecological language throughout | 0.12 | Resists premature closure and preserves memory of emergence | `catch`, `steep`, and `rehydrate` may be opaque or imply progression |
| Plain namespaced identifiers with ecological display language | 0.48 | Stable machine terms with a breathable human register | Requires a small alias table |

These values are collaboration-generated design priors. They make the choice legible for discussion and remain distinct from measurements, confidence scores, or calibrated forecasts.

The selected working moves are:

| Identifier | Human-facing interpretation | Material effect |
| --- | --- | --- |
| `observe` | notice or catch an observation | Preserve a decision-bearing signal without promising an artifact |
| `hold` | let the material steep | Keep a billet or question reachable while fit develops |
| `form` | project a working preparation | Create the smallest skill, projection, reference, or capsule with a receiver |
| `use` | exercise in material work | Let a receiving outcome provide the outside view |
| `settle` | retain, fold, rest, compost, or retire | Release ordinary attention while preserving the appropriate return path |
| `reopen` | rehydrate from fresh signal | Resume from human correction, artifact behavior, changed conditions, or independent evidence |

`catch` remains a display word rather than an identifier because exception handling gives it a strong technical meaning. `steep` and `rehydrate` remain interpretive labels because they usefully carry time and transformation while plain identifiers support named-entity recognition. `project` remains a relationship noun in this repository, so `form` names the lifecycle move.

Route decisions such as `create_now` and `settle_or_fold` remain separate from lifecycle moves. A route selects the next action; the lifecycle vocabulary describes the affordance's current movement through attention. Dormancy is a quiet settled disposition: the item leaves ordinary routing, keeps provenance, and carries a wake condition.

```text
observe → hold → form → use → settle
   ↑                            │
   └──────── reopen ────────────┘
```

The collaboration affordance can outlive any one platform skill. Formation maps that affordance into the present repository transport while preserving source material for other teams and future platforms.

## Skill composition and interpretive augmentation

Skills can work together through several distinct relations:

| Relation | Owner shape | Use |
| --- | --- | --- |
| **Peer composition** | Each skill owns a distinct receiving result | Sequence or combine jobs without merging their contracts |
| **Task-bound projection** | One portable contract owns the selected behavior | Bind a skill to one task, tool surface, authority scope, and lifetime |
| **Conditional context** | The active skill owns the result | Load uncommon source or domain detail only for the relevant branch |
| **Interpretive lens binding** | The primary skill owns completion; the lens owns only a declared attention effect | Add a temporary vantage, counterview, register, or probability-of-what pass |

An interpretive lens binding names its source, foregrounded attention, likely constitutive silence, receiving task, and exit condition. It remains a non-routable task relation rather than another descendant skill. A lens can suggest a question or alternative; current task authority decides whether that changes the work.

Verbalized sampling supplies one concrete lens binding: the owning skill retains its result while the lens names the probability object, candidate-set boundary, generated design priors, and distinction among probability, confidence, fit, priority, and desirability. It exits after the receiving decision. An independently recurring trigger, result, and completion can return it through ordinary skill candidacy.

## Large-corpus sampling

### Pass one — direct anchors

Read the sources most likely to change the immediate route:

- the current skill catalog and candidate queue;
- the material work that produced the observation;
- the nearest collaboration account;
- one or two source authorities for the underlying contract.

### Pass two — deliberate variation

A second pass samples adjacent structures with different organizing logics:

- recovery and gap-utility routing;
- temporal horizons and deferred candidates;
- indeterminacy and resting concepts;
- evidence-bearing continuation and stop conditions;
- folding, precipitation, and re-entry;
- team-capability and cross-platform transfer readings;
- a counterexample, failed attempt, or near-miss when available.

The second pass earns its place when variation could reveal a different route, missing boundary, or stronger receiving form.

### Database-metadata sweep

Database schemas can expose stable distinctions that prose search misses. Useful fields include:

- lifecycle state separate from currentness;
- candidate, drafting, precipitated, settled, folded, and retired states;
- outcome types that preserve partial, pivoted, failed, abandoned, and ongoing work;
- source band, visibility, disclosure, drift risk, and last-reviewed date;
- artifact genre separate from maturity;
- execution authority and research status;
- companion, lineage, source-page, and thread relations;
- rotation or alternative-vantage markers.

Metadata informs vocabulary and route separation. The repository skill remains self-contained and carries a compact instruction surface in place of a workspace database replica.

### Corpus cautions

A varied workspace sampling pass showed that exploratory collections contribute vocabulary and situated observations while only a small portion changes the artifact in front of the team. Sparse research collections support qualitative route decisions rather than empirical skill-effectiveness inference. Blank drift-risk, instruction-implication, research-link, or lifecycle fields remain unclassified state rather than negative evidence.

These findings support a compact initial skill and natural-use observation. They do not support a performance dashboard or a statistical promotion gate.

### Research release

Research settles when another source or schema row is unlikely to change the route, boundary, smallest action, or return trigger. Further material remains reachable through source links rather than active in the skill.

## Compact collaboration account

```yaml
collaboration_account:
  observation: "what happened in materially meaningful work"
  decision_effect: "which future collaboration decision changed"
  current_owner: "active skill, candidate, or genuine gap"
  route: "create_now | iterate_now | queue_with_trigger | observe | settle_or_fold | merge_or_retire"
  smallest_action: "the one useful change"
  evidence_band: "observed | human_declared | source_supported | inferred | open"
  transfer_boundary: "where the conclusion can travel"
  reentry_trigger: "what new signal reopens stewardship"
```

This is a residue shape rather than a required form. Existing prose threadkeeping can carry the same fields.

## Compact skill billet

```yaml
skill_billet:
  candidate_name: "transferable capability name"
  receiving_job: "the coherent job a future skill could own"
  current_evidence: "why the contract appears useful"
  active_owner_overlap: "none or adjacent skill"
  instruction_yield: "future behavior the skill would support"
  forge_condition: "the real task or recurrence that makes creation timely"
  resting_surface: "issue, planning page, or threadkeeping address"
```

## Extended scenarios

### Scenario: An active skill has decision-changing friction

- Given an active skill owns the receiving job
- And material use reveals one instruction gap that would change the next result
- When another similar use is prepared
- Then the route is `iterate_now`
- And the narrowest behavior-changing instruction receives revision

### Scenario: A portable contract has no receiving job yet

- Given a collaboration surface contains a durable cognitive contract
- And several future skills could be forged from it
- And no immediate task selects among those forms
- When stewardship reviews the candidate
- Then the route is `queue_with_trigger`
- And the contract remains available with a forge condition

### Scenario: Two skills converge on one job

- Given two skills route from materially identical triggers to the same receiving result
- And one owner can preserve the useful rules and source links
- When duplicate routing increases attention cost
- Then the route is `merge_or_retire`
- And Git history or threadkeeping preserves the lineage and future re-formation trigger

### Scenario: A second research pass confirms the current route

- Given direct sources and a varied second sample support the same route
- And a database-metadata sweep adds vocabulary without changing the decision
- When further retrieval would repeat the evidence shape
- Then research settles
- And the selected skill action proceeds with the source boundary visible
