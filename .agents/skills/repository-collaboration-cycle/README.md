# Repository collaboration cycle

Carry an authorized repository task from current-state recovery through one
reviewable result, fitting evidence, and an exact continuation point.

## Start here

- Read [`SKILL.md`](SKILL.md) for the authoritative cycle, authority boundaries,
  evidence rules, scenarios, and completion criteria.
- Use the [repository collaboration cycle runbook](../../runbooks/repository-collaboration-cycle.v0.1.md)
  for the repository-specific phase sequence and command routes.
- Return to the [repository skill catalog](../README.md) to select the domain
  skill that owns the material change.

## What this skill returns

A handback carries:

- one-sentence scope;
- changed artifacts and purpose;
- exact validation command and normalized result;
- environment changes that affect behavior or reproduction;
- the active Issue or pull request;
- the next receiver; and
- one exact action that resumes the work.

The task’s grants continue to govern mutation, pull-request creation, merge,
publication, deployment, and destructive operations throughout the cycle.

## Concrete example

**Situation:** A cold collaborator receives an authorized layout repair with an
active Issue, acceptance criteria, and a requirement for browser evidence.

**Use:** Reconstruct the branch and source truth, prepare the locked dependencies
and named browser needed by acceptance, apply the owning layout and verification
skills, run the focused checks, and place the result in one review-ready pull
request.

**Observable return:** The pull request names the repaired behavior, exact checks
and results, browser coverage, remaining evidence boundary, human merge decision,
and post-merge command that resumes the work.

## Cycle

1. Re-enter current source, Git, GitHub, planning, and threadkeeping state.
2. Classify the route as direct action, primary work with bounded support, or a
   held route with one release signal.
3. Prepare only the environment selected by the evidence question.
4. Bind the issue-specific branch and preserve unrelated work.
5. Execute through the domain owner and integrate any bounded return.
6. Run the smallest source-owned checks that answer acceptance.
7. Deliver on one named receiving artifact and record exact re-entry.
