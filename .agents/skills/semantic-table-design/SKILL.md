# Semantic table design

## What

A source-owned table contract that preserves precise lookup, comparison, units, qualifications, and row/column relationships across visual and extracted forms.

## When

A table's content, layout, semantics, generated representation, or receiving use is being assessed or changed. Direct source reasoning remains sufficient for a small correction with an already established owner.

## Boundaries

The authored table or generator owns meaning. Native HTML owns baseline relationships. Custom attributes support named receivers; arbitrary model or ATS ingestion remains an empirical question. A geometry signal identifies a review candidate rather than establishing accessibility conformance.

## Result

A bounded table-family disposition: reader job, owner, column roles, scroll owner, semantic/extraction relationships, affected states, fitting observations, and remaining uncertainty.

## Rules

1. Name the reader operation: lookup, compare, enter, reconcile, or inspect evidence. Keep the table when two-dimensional relationships or precise values serve that operation; a chart may be a companion for patterns.
2. Trace authored markup, generator, shared styles, declared mirrors, report/print output and publication projection before editing. Historical copies retain their comparison role.
3. Use caption or close orientation, native headings, and fitting row/column scope. Review complex spans and header associations explicitly. A simpler table is a valid result.
4. Classify identity, numeric value, status, prose and identifier columns. Preserve meaningful numbers and units, ordinary word boundaries and usable cell measures. Give identifiers their own wrapping policy.
5. Let necessary comparison geometry exceed the viewport inside a named, keyboard-reachable local scroll region. Reflow surrounding prose and controls. Inspect individual cell reading measure as well as the whole table.
6. Use restrained grouping, alignment, whitespace and selective emphasis to support scanning. Preserve the route's existing visual language. Color supplements text and structure.
7. Derive supplemental `data-label` values from the same source as visible labels. A useful detached record carries topic, row identity, field label, value and applicable unit/status. Add stable identifiers when a receiving contract consumes them.
8. Preserve zero, blank, unavailable, invalid, inapplicable and uncertainty according to the source contract. Keep qualifications adjacent to the values they qualify.
9. Observe every affected column and material disclosure/state. Separate source presence, rendered geometry, accessibility relationships, keyboard behavior and deterministic extraction. Declare what each observation establishes.
10. Repair the smallest shared owner that actually covers the affected family. Self-contained artifacts may share a build-time contract while retaining dependency-free output.
