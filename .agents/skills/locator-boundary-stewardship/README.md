# Locator boundary stewardship

Keep a public collaboration record understandable and continuable while exact
gated coordinates remain recoverable through an authorized resolver.

## Start here

- Read [`SKILL.md`](SKILL.md) for the authoritative receiving forms, stable-key
  rules, paired-receiver sequence, and completion boundary.
- Return to the [repository skill catalog](../README.md) when source-authority
  mapping or issue-chain coordination owns the broader result.

## Four receiving forms

| Reader need | Fitting form |
| --- | --- |
| The same job has an accepted public destination | Accepted public receiver |
| Exact gated lineage remains useful to an authorized collaborator | A stable public key whose value reveals no gated coordinate—an operator-blind source key—plus resolver mapping |
| The useful meaning fits directly in the record | Local explanation |
| The complete artifact lives in the same repository | Repository-relative source link |

## Concrete example

**Situation:** A pull-request description cites a gated working page whose
rationale materially affects future re-entry.

**Use:** Preserve the page’s public-safe title, role, contribution, evidence
standing, and re-entry condition in the pull request. Assign a stable public
key whose value reveals no gated coordinate—an operator-blind source key—and place the exact coordinate, access boundary, observation date,
and mapping state in the authorized resolver.

**Observable return:** A public collaborator can understand and continue the
work from the pull request, while an authorized collaborator can recover the
exact source through the paired resolver. Each receiver carries its own
acceptance state.

## Working path

1. Name the receiving reader, publication boundary, and decision.
2. Bind an observation cutoff and classify each consequential reference.
3. Prepare the public semantic record and authorized mapping around one stable key.
4. Replace the locator while retaining rationale, standing, contribution, and re-entry.
5. Record affected artifacts, dispositions, resolver standing, and next receiver.
