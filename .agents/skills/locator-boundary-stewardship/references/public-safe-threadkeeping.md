# Public-safe Threadkeeping

Load this profile when Threadkeeping crosses a publication boundary while exact gated provenance remains useful to authorized collaborators.

## Receiving result

The public record preserves decisions, rationale, source roles, evidence standing, settled alternatives, and the next re-entry position. It remains complete for public comprehension, while an authorized resolver adds exact lineage.

Threadkeeping remains distinct from complete transcripts, runtime telemetry, security event logs, build output, and deployment state. Those records stay with their behavior and evidence owners.

## Public source record

Retain the fields that materially support interpretation and return:

```yaml
source_key: "operator-blind stable key"
public_safe_title: "reader-usable source name"
relationship: "the source's role in this record"
material_contribution: "what it changed or clarified"
standing: "evidence or publication standing"
repository_artifact: "optional relative receiving path"
source_order: "stable order within this artifact"
disposition: "public_receiver | private_lineage | local_explanation | repository_local_source"
reentry_condition: "the event that makes renewed source resolution useful"
```

## Resolver counterpart

The authorized resolver pairs the same `source_key` with the exact coordinate, access boundary, observation date, resolver authority, accepted public receiver when present, and review state.

## Practice

1. Allocate keys by first appearance within a stable source family.
2. Reuse a key when the same source performs the same role again in one artifact.
3. Allocate a distinct relation key when one source performs materially different jobs across artifacts.
4. Preserve source order so a future collaborator can reconstruct the reasoning path.
5. Keep public-safe titles even when the source rests in private lineage.
6. Route outward only when a public receiver performs the same reader job and carries fitting publication standing.
7. Prefer a repository-local continuation when the local artifact already contains the complete usable account.
8. Convert raw coordinate lists into titled source records whose relationships and contributions remain explicit.
9. Close with occurrence, identity, key, disposition, and resolver-row counts. Keep these dimensions separate when repeated sources make them differ.

## Naming posture

`Public-safe Threadkeeping` describes safety at the locator boundary. Privacy, secrecy, correctness, and security claims retain their own evidence and owners. `Locator-boundary stewardship` remains the portable skill owner; this profile supplies the Threadkeeping-specific record shape.

## Profile completion

The bounded Threadkeeping family carries zero exact gated coordinates, every relation has a source key or fitting public/local receiver, the resolver preserves authorized lineage, and the public record remains directly usable on its own.
