# Declarative skill authoring

Turn a recurring, useful way of working into a portable contract that another
collaborator can route, apply, complete, and revise while task authority and a
flexible working register remain visible.

## Start here

- Read [`SKILL.md`](SKILL.md) for the authoritative authoring contract and
  revision rules.
- Return to the [repository skill catalog](../README.md) to inspect neighboring
  contracts before creating a new route.

## What this skill returns

A completed authoring pass makes five things easy to find:

1. the recurring job and trigger;
2. the result the skill owns;
3. the authority and transfer boundaries;
4. the smallest action-bearing method; and
5. the completion, recovery, and revision conditions.

Direct reasoning remains the right outcome when it already supplies the result
with less navigation.

## Concrete example

**Situation:** Several projects repeatedly need a public collaboration record
that preserves useful rationale while gated coordinates stay with an authorized
resolver.

**Use:** Compare the requested receiving result with standing guidance. When
the result is new, write a third-person description, define the
What/When/Boundaries/Result contract, add the rules that preserve semantic
identity, and retain one boundary scenario.

**Observable return:** A fresh-context collaborator can recognize a fitting
task, create the two coordinated records, identify completion, and route a
resolver mismatch back to its owner.

## Authoring path

1. Define the recurring job and material contribution.
2. Write capability-first metadata and the core contract.
3. Add rules and a sequence where order changes the result.
4. Keep only examples that distinguish an important branch.
5. Move uncommon detail into directly linked references.
6. Inspect routing language, authority, completion, and the next signal from an adjacent owner.
