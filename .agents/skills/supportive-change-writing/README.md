# Supportive change writing

Write changes so the desired state, responsible actor, evidence, boundary, and
next revisable action are easy to find. This skill supports warm, direct prose
while preserving technical precision, human variation, and necessary safety
and compatibility constraints.

- [Read the authoritative skill contract](SKILL.md)

## Use it when

Use this skill for material revisions to READMEs, plans, Issues, instructions,
change explanations, interface copy, or other human-facing repository prose.

## What it returns

- the useful state or ability in the lead;
- concrete actors, actions, objects, and consequences;
- evidence-calibrated claims and locally attached boundaries;
- negations classified by their actual job; and
- a bounded close that tells the reader what can happen next.

## Concrete example

| Part | Example |
| --- | --- |
| Situation | An instruction says, “Do not publish internal URLs or forget to verify the links.” |
| Use | Keep the privacy boundary and pair it with the desired action: “Publish locator-safe prose through approved public routes. Verify every public link before handback; keep gated locators with the authorized resolver.” |
| Observable return | The reader can identify the publication path, the required verification, the protected material, and the location that retains exact lineage. |

## Working route

1. Identify what the reader should be able to understand or do.
2. Classify each negation as generative, safety-critical, definitional, epistemic, executable, or quoted source language.
3. Lead with direct verbs and concrete nouns; pair load-bearing boundaries with their replacement behavior.
4. Preserve exact identifiers, quotations, governed terms, and executable conditions.
5. Distinguish verified fact, supported inference, practitioner observation, proposal, and open question.
6. Review headings, bullets, tables, examples, and code-layer guidance in their receiving context.
