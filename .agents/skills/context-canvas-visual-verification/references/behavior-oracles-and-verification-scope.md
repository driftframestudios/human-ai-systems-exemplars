# Behavior oracles and verification scope

This reference helps a collaborator select a browser observation that distinguishes the visitor’s intended reading or interaction from a credible fault, then carry that evidence through a coherent repair. The parent skill owns the final verification return. Authored HTML, CSS, runtime behavior, accepted contracts, and current task authority retain their source and decision roles.

## Fit and release

Use this reference when a visible defect persists through a geometry pass, a regression check reports success without exercising its named failure, an injected fault behaves differently by engine, or new findings repeatedly reopen a family campaign. The smallest useful application is one behavior, one distinguishing observation, one source-bound result, and the evidence that would reopen it.

Direct source inspection remains fitting for a behavior-neutral edit. A source comment or ownership-map correction can often settle through source review. Moving a stylesheet or changing a visible label reopens its affected cascade or presentation evidence. An iframe’s internal import, edit, or recovery state belongs with its runtime owner and the stateful-artifact contract. This reference releases when the chosen observation answers the material question and another campaign would leave the receiving decision unchanged.

## Bind one material observation

Record only the fields that can change the decision:

| Field | Question |
| --- | --- |
| Visitor behavior | What can a visitor read, reach, recognize, or operate? |
| Current source | Which accepted revision and source/projection owner create it? |
| Plausible fault | Which credible change would defeat that ability? |
| Observable oracle | What measured or visibly inspected state distinguishes the two? |
| Environment | Which engine, viewport or container, state, media, and font conditions matter? |
| Consequence | Why does the distinction affect reading or use? |
| Remaining receiver | Which adjacent observation or decision remains with another owner? |

When the accepted baseline or reported environment is unavailable, record the current-source observation and keep historical reproduction with its named receiver. Return one interpreted result through the existing Issue or PR; the local evidence retains exact configuration and captures.

The oracle follows the claimed behavior. Selector existence and class counts can establish inventory. Computed properties can establish a winning cascade rule. Text fragments can establish measured text placement. A focused image can reveal painted slicing or overlap. Each signal keeps its own claim rather than becoming a proxy for the entire visitor experience.

## Fragmentation and containment

For a reading-order claim, locate the named heading and the actual continuation it governs. Inspect nonempty text fragments and the semantic relationship that makes their order meaningful. Arbitrary nearby text and the outer element box can miss a later fragment or select an unrelated region.

Pair geometry with focused paint inspection when the mechanism includes multicolumn fragmentation, clipping, transforms, or a known engine-specific paint defect. A correctly placed Range rectangle can coexist with visible slicing, duplication, or overlap. Retain that disagreement as a finding and choose an observation that can establish the reader’s actual result.

Keep local containment separate from document containment. A wide table can exceed its inner scroll region while the figure remains inside the page and clear of a fixed rail. Page `scrollWidth` helps observe positive overflow; directly inspect content hidden by clipping or negative positioning. Borders, outlines, shadows, focus rings, and other consequential painted extents receive their own reserve or focused view.

Expected typography keeps a precise exception. A raised footnote reference may extend above its paragraph’s ordinary line box while remaining inside the enclosing reading region. The test can preserve paragraph inline containment and use the named outer region for that reference’s vertical bounds. Ordinary paragraph text retains its own full containment assertion. A discovered exception refines the owning relation and leaves neighboring assertions active.

## Demonstrate the fault and restore the receiver

A positive observation establishes the intended state in the declared environment. A counterfactual observation establishes that the check distinguishes the named fault there. Both are useful and separate.

1. Read the accepted source and reproduce the fault from a frozen baseline where possible.
2. Select the smallest perturbation that changes the material relationship: place a label inside a fragmented region, restore a misleading table-format class, or move a continuation before its heading.
3. Confirm that the perturbation actually creates the intended state in that engine and width. A compact paragraph can remain one fragment, so merely changing its wrapper leaves the fault unexercised.
4. Check that the relevant assertion detects that fault with a useful failure message. An unrelated selector error or resource failure supplies harness evidence.
5. Restore the source or use a fresh document, then establish the positive state again. An unconditional cleanup path keeps later cases attached to their declared input.

A fault can reproduce in one engine and remain unexercised in another. Preserve that distinction in the return while continuing positive checks in each supported engine. Engine scope follows observed behavior; a shared browser-engine family still leaves native application integration and user configuration to their own observations.

When an oracle fails, preserve the valid case and diagnose the discrepancy before widening tolerances. A changed tolerance names the legitimate variation it admits and the fault it continues to reject. Failure-message ordering can improve diagnosis while every material assertion remains active.

## Select the next check from the current repair state

Discovery, repair, final verification, and handoff answer different questions. They can share existing commands while retaining their distinct purpose.

| Current question | Fitting next observation |
| --- | --- |
| One source-owned uncertainty can choose the repair | A focused source or browser experiment at the discriminating state |
| A route-local behavior changed | The affected route, its relevant modes, and any meaningful sibling or control |
| A shared component, cascade seam, or route-family boundary changed | The affected consumer family and dependency-sensitive states |
| A broadly loaded core or system-wide visual role changed | The complete applicable route reference, plus focused behavior checks |
| The final coherent repair is ready for acceptance | Required checks on the named closure candidate after its last relevant change |
| A late finding changes an owner or an assertion | A named reopening of affected source, states, and evidence |

A closure candidate is a bounded statement of the final source, route set, owners, assertions, and required evidence. It gives a broad campaign a coherent input. A candidate can remain open while a focused probe resolves a known uncertainty; acceptance follows the required result rather than a favorable count or modeled probability.

A late finding carries a repair owner and an evidence effect. A route-only markup correction reopens that route’s behavior and dependent source checks. A shared CSS change reopens its actual consumers. A new assertion reopens the behavior it claims to observe, including the corresponding fault control. Adding another reading route expands the declared inventory. Previously completed checks remain useful only within their unchanged source, dependencies, states, and assertions.

Harness failures keep their own outcome. Preserve completed cases, identify missing cases, and distinguish an application finding from a failed observer or failed process start. Repeated campaigns, launches, cases, screenshots, and elapsed durations retain their own quantities. Raw evidence remains local; the PR body or other named receiver holds one normalized result and its limits.

## Worked decisions

### A multicolumn region passes geometry while paint repeats text

- Given a heading and lead paragraph have the intended semantic order
- And text-fragment geometry reports the intended heading and continuation placement
- When a focused engine capture shows an extra painted copy of the lead paragraph above the heading
- Then the visible duplication remains a finding
- And the repair returns to the owning fragmentation boundary before final family verification

### A fault fixture remains a valid one-block paragraph

- Given a short paragraph is moved into columns for a controlled fault
- When that engine keeps the whole paragraph in one fragment
- Then the attempted fault remains unexercised in that environment
- And a naturally fragmented source case or another declared perturbation supplies the distinguishing observation
- And the positive paragraph-containment check retains its independent result

### A late route-local fix follows a family pass

- Given the accepted family observation is attached to a named source and assertion set
- When a later finding changes one route’s markup while shared dependencies remain unchanged
- Then the route and its dependent checks reopen
- And still-applicable family observations keep their original scope
- And any mandatory final gate runs on the final candidate before handoff

These scenarios express intended decisions. Actual source, executed checks, focused paint review, and independent acceptance establish the receiving case.
