# Repository attribution stewardship

Place citation, copyright-holder identity, contribution credit, licensing,
public-document notices, and machine-readable metadata in the carriers that
actually own those jobs.

## Start here

- Read [`SKILL.md`](SKILL.md) for the authoritative carrier map, decision
  boundaries, adaptation rules, operating sequence, and completion criteria.
- Return to the [repository skill catalog](../README.md) when a publication or
  cross-repository lineage question needs source-authority mapping.

## Choose the carrier by the job

| Need | Typical carrier | What it establishes |
| --- | --- | --- |
| License terms | `LICENSE` | Current repository license text |
| Copyright-holder record | Repository-defined `AUTHORS` convention | The identity role defined by that file and governance |
| How to cite the work | `CITATION.cff` | Standard citation metadata from a confirmed decision |
| Who contributed a change | Git author metadata, agreed trailers, and reviewed pull requests | Contribution identity and chronology |
| How contribution and publication work | Governance guidance | Repository practice and decision routes |
| Attribution inside a standalone public document | Copy-local metadata and visible notice | Context that travels with that document |
| Machine comparison | Bounded structured projection | Exact distinctions while named sources retain authority |

## Concrete example

**Situation:** A reader asks how to cite a repository and who implemented its
latest feature.

**Use:** Route the citation request to `CITATION.cff`. Route implementation
credit to truthful Git metadata and the reviewed pull request. Preserve the two
questions as distinct carrier jobs.

**Observable return:** The reader receives a standard citation from the citation
carrier and an inspectable contribution record from repository history. Each
carrier keeps its stated coordination scope.

## Working path

1. Name the actual need: citation, holder identity, contribution, license,
   public notice, adaptation, or machine comparison.
2. Read the governing carriers and current repository state.
3. Map each value to its source owner and each open rights decision to a named
   human receiver or qualified counsel.
4. Change the smallest source-owning artifact and preserve accepted notices.
5. Parse structured files, resolve paths, compare governed values, and observe
   affected public documents.

This skill is self-contained in [`SKILL.md`](SKILL.md). Exact legal text and
rights decisions remain with their named sources and human decision routes.
