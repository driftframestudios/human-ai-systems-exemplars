Chimeric Prototype v0.1.1

Specification-by-Example

Behavior Example Bridge

A bridge architecture that turns verbal agreement into concrete examples, then lets accepted examples become living specifications, tests, or implementation guidance. This single-file artifact preserves human-readable editing, SVG visualization, JSON/JSON-LD structure, semantic locality, recovery calibration, and an AI collaboration prompt capsule.

Quick Use

Use when

A team agrees in principle but needs concrete examples of context, event, and observable outcome.

This restores

Behavioral clarity across domain experts, designers, engineers, testers, reviewers, and AI collaborators.

Good next question

Can we express this as Given / When / Then?

Usually hands to

Unit-test-first Design, Software Architecture Views, HEART Chart, Service-design Blueprint, Upstream Revision Loop.

Semantic Locality

  • Prefer “observable behavior example” over “acceptance test” until implementation protection is intended.
  • Preserve Given / When / Then as context, event, and observable outcome.
  • Use “needs revision” rather than failure language when evidence changes the read.
  • Route accepted examples into Unit-test-first Design when behavior deserves executable confidence.

Recovery Calibration

  • Strain cue: rules are debated abstractly.
  • Stabilizing read: the collaboration needs concrete examples.
  • Restored state: behavior is expressed as context, event, and observable outcome.
  • Routes: Unit-test-first Design, Software Architecture Views, Service-design Blueprint, HEART Chart.

Advanced Identity Registry

Stable identity remains separate from focus-view order and visibility.

Source Note

This prototype represents Specification-by-Example: Behavior Example Bridge as a Core Architecture chimeric twin. It treats examples as a bridge from human-readable rule discussion to implementation-facing living specifications or tests when useful. The local adaptation preserves two modes: discovery-facing examples and executable-facing specification candidates.

The source lineage includes Gojko Adzic’s Specification by Example, Kamil Nicieja’s Writing Great Specifications as the local source path noted in the Core Architectures source material, and Cucumber / Gherkin references for Rule, Example / Scenario, Given, When, and Then. This artifact remains tool-neutral: it is Gherkin-adjacent, but does not claim exact Cucumber compatibility.

  • Gojko Adzic — Specification by Example: source anchor for examples as collaborative specification and living documentation.
  • Kamil Nicieja — Writing Great Specifications: source path noted in the Core Architectures source document for the local collaboration lineage.
  • Cucumber — Gherkin Reference: source anchor for Rule, Example / Scenario, Given, When, Then, and observable outcome language.

No custom source-local annotation language appears in artifact-facing content. All exported data uses ordinary fields and stable IDs.
