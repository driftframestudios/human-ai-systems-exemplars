# Narrative Sampling Tableau — Prototype Addendum v0.1

## Working determination

**Verbalized Sampling** remains the method name and research anchor.

**Narrative Sampling Surface** is the canonical schema type.

**Narrative Sampling Tableau** is the human-facing name of the chimeric artifact.

The artifact expands a generative-diversity technique into a source-linked collaboration surface. It preserves the difference between a model-verbalized distribution, a planning judgment, a dimensional-fit assessment, and a calibrated forecast.

## Why the Tableau is a tableau

The surface presents a field of alternatives rather than one answer stream. It lets collaborators:

- fan out materially distinct possibilities;
- preserve an explicit open tail;
- compare probability, confidence, fit, desirability, and priority as separate concepts;
- score candidates across selected dimensions;
- inspect evidence, assumptions, tradeoffs, and failure modes;
- compare runs and condition changes;
- record hypotheses about probability shifts;
- retain decisions, dissent, and update triggers;
- route the current terrain into another architecture or research flow.

## Seed scenario

The embedded scenario uses the Conation Motion naming exploration from the planning bundle.

The baseline asks one term to serve every naming layer.

The comparison variant allows canonical, technical, public display, and authored labels to remain separate.

The values are **uncalibrated planning estimates** derived from the prior exploration. They are intentionally marked uncalibrated and non-empirical.

This seed is useful because it demonstrates:

- a genuine stability–legibility tradeoff;
- the effect of changing one structural condition;
- a probability-shift hypothesis with a stated mechanism and falsifier;
- a decision in which dimensional fit and future refactorability matter alongside probability;
- routing into Strategy Canvas, Context Tree, Practitioner Judgment Probes, Research Atlas, and the Terminological Registry.

## Core Architecture routing

The route registry mirrors the stabilized seven-family, twenty-card Core Architecture set.

Each card retains:

- one canonical family home;
- a primary cognitive move;
- an S/I/R distribution;
- route triggers;
- expected return state;
- a working chimeric-prototype reference.

The S/I/R values answer:

> What is the probability that a skilled collaborator’s first useful use of the card primarily begins in Solution, Implementation, or Recovery work?

They remain cognitive-origin priors rather than fixed identity.

Recovery Routing and Revision remains both:

- a full family with dedicated cards; and
- a routing layer that can return the collaboration to any other family.

## Prompt Capsule

The AI Prompt Capsule lowers the cost of a complete verbalized-sampling request by composing:

- the decision;
- the fully stated probability object;
- population and horizon;
- conditions and exclusions;
- candidate-set semantics;
- multiplicity and tail instructions;
- requested estimate kind;
- dimensions and weights;
- comparison run;
- probability-shift question;
- gap and route requirements;
- output contract.

The generated request leads with desired output state and preserves hard epistemic boundaries.

The prototype now projects that request through `prompt-capsule/0.1.0`. Its
plain GitHub Flavored Markdown view is complete on its own; the optional
skill-assisted view adds public collaboration methods while preserving the
same represented sampling state and fingerprint. Visible, copied, downloaded,
and programmatic Markdown share one byte stream. Related loops remain
condition-bound routes, and the JSON sampling state retains semantic
authority.

The portable request includes the outcome success criteria, outcome and
condition-profile boundary sets, each candidate's declared dimension scores,
and a compact comparison with the named baseline run. When a formal
statistical-fit method is enabled, its complete declared state enters the
projection and fingerprint and appears in a dedicated Markdown subsection.
Imported candidates provide one finite zero-to-ten score for every declared
dimension, keeping absence distinct from a measured zero. Changes to the
baseline or comparison run, commensurability, probability role, and formal-fit
controls refresh the visible Prompt Capsule alongside its programmatic view.

## Visual doctrine

Probability uses a common zero-to-one scale.

Intervals share the same scale.

Run differences use a zero-centered common scale.

Dimensional fit uses a numeric matrix and weighted bar comparison.

Every visual value also appears in a table or inspector.

The prototype uses no pie or radar forms.

## Stable identity

Run, candidate, dimension, gap, hypothesis, decision, and route IDs remain stable while:

- cards are sorted;
- filters change;
- active runs switch;
- a variant is duplicated;
- probability values change;
- target routes are selected;
- view state changes.

A generated export is a projection of the current state. It does not replace the source planning records.

## Publication posture

The seed is a private working example.

Public-safe generation would exclude:

- private locators;
- unreviewed source-local annotation;
- unreviewed inference;
- internal source notes.

A public surface would preserve:

- stable IDs;
- public-safe source markers;
- estimate and calibration status;
- disclosed omissions;
- table equivalents;
- research and route references.
