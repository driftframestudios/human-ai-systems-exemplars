```yaml
research_payload:
  id: "prototype-exemplars.strategy-canvas-domain-anchor-atlas.v0.1"
  question: "Which starter dimensions help a group begin while preserving local definitions, evidence, and revision authority?"
  completion_condition: "Every recommended dimension carries definition, anchors, evidence prompt, abstention condition, and source standing."
```

## Preset contract

A preset is a starting hypothesis. It creates editable dimensions and records its source/version. A participant reviews each definition and anchor before the first round.

The [machine-readable evidence registry](../../../core-architectures-chimeric-prototype-current-pack-v0.1/strategy-canvas-system-v0.2/strategy-canvas-evidence.v0.1.json) connects change-oriented starter dimensions to `organizational-readiness-boundary`. That entry keeps shared commitment and collective capability distinct from local offering levels and from any claim that this worksheet measures readiness.

Each dimension includes:

- stable ID and concise label;
- local definition;
- low, middle, and high anchors;
- optional five-point anchor set;
- evidence prompt;
- abstention condition;
- consequence statement;
- initial ERRC state, when intentionally supplied;
- domain/source standing;
- responsible reviewer;
- aliases for import matching.

## Cross-domain collaboration pack

| Dimension | Low anchor | Middle anchor | High anchor | Evidence prompt |
| --- | --- | --- | --- | --- |
| access | participation depends on exceptional help | common routes work with known gaps | intended participants can enter and continue through supported routes | Which participants completed which route under what conditions? |
| clarity | purpose and next action remain ambiguous | informed participants can proceed with occasional clarification | purpose, state, consequence, and next action are recoverable at each decision | Where did participants pause or request explanation? |
| continuity | handoffs rely on memory or private context | key artifacts travel with some manual reconstruction | state, rationale, evidence, and next position travel together | Which handoff required reconstruction? |
| evidence traceability | claims lack visible basis | principal claims link to partial sources or observations | consequential claims carry source standing, limits, and review route | Can a reviewer recover the basis for each major reading? |
| recovery | correction requires restart or specialist intervention | common failures have documented local repair | participants can identify, repair, and resume from the nearest stable state | What was the last recoverable state? |
| adaptability | change requires broad coupled edits | known variants use defined extension points | local variation is supported through clear contracts and bounded overrides | Which change crossed an unexpected boundary? |
| trust legibility | authority and automation are difficult to distinguish | major roles are stated | human, AI, source, system, and derived contributions retain visible standing | Can a participant tell who supplied and who accepted each value? |
| time to useful state | value arrives after lengthy setup | common cases reach value after moderate configuration | a new participant reaches a meaningful result through a short guided route | How long and how many interventions did first useful state require? |

Anchor research must name the relevant platform boundary, service level, users, and evidence horizon. “High interoperability” becomes usable only when supported formats, semantic fidelity, failure handling, and ownership are specified.

## Preset assembly flow

1. Choose a domain or blank canvas.
2. Preview definitions and anchors before adding dimensions.
3. Select 5–12 dimensions that can change the named decision.
4. Merge aliases or near-duplicates deliberately.
5. Edit anchors for local context.
6. Attach evidence and reviewer.
7. Confirm authored order.
8. Record removed preset dimensions and rationale in the setup receipt.

## AI support boundary

An AI collaborator may propose candidate dimensions, definition variants, anchor language, missing evidence, and possible collisions. The interface labels each proposal and requires human adoption before it joins a round. AI-proposed presets preserve source prompts and model/tool/date metadata in their evidence envelope.

## Falsifiers

- A preset enters scoring without definition review.
- Generic labels such as “quality” or “innovation” retain no local anchor meaning.
- Domain authority is implied by an exploratory preset.
- An AI-proposed dimension appears as human-approved.
- Two dimensions measure the same construct while the curve implies independent factors.
- A dimension stays because it is fashionable while it cannot change the receiving decision.

## Completion gate

- The cross-domain pack validates against schema v2 and renders in both expressions.
- Every included dimension carries three usable anchors and an abstention condition.
- Import preserves preset source/version and local edits.
- Removed dimensions remain in a setup receipt rather than silently disappearing.
- At least one practitioner from each promoted domain reviews definitions, anchors, and boundary language.
- AI-proposed dimensions require explicit adoption and retain proposal standing.
