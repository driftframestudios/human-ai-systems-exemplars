## Formed active contract

### `context-canvas-visual-verification`

- **What:** Select and exercise proportionate visual and browser evidence for one Context Canvas visitor-surface question.
- **When:** Layout, CSS, responsive behavior, interaction state, print, forced colors, or a visible regression can change.
- **Boundaries:** Authored source owns intent; screenshots are comparison evidence; resting captures leave interaction states open; prototype interiors retain separate owners.
- **Result:** A source-bound all-page, affected-family, or focused observation with exact command, normalized result, coverage limit, environment risk, and next receiver.

The skill forms as an exercised draft. The contrast cycle is its first natural-use account, and milestone-22 issue #151 is its next independent use. A near miss—such as using the all-page screenshot run to claim hover or print behavior—can change its routing or evidence rules.

The former `Visual-reference cycle` billet precipitates into this broader contract. `Visual-fingerprint stewardship` folds into its fingerprint-versus-regression rule. The new name reflects the receiving job rather than one tool or artifact.

## Existing-owner revisions

### `context-canvas-css-ownership`

The conditional `surface-color-and-state-roles` reference now carries:

- immutable palette roles versus inherited active roles;
- complete unvisited and visited pairs at each painted owner;
- nested background resets;
- effective paint across alpha, gradients, filters, and fallbacks;
- hover, focus, visited, print, forced-color, viewport, and engine evidence;
- visited-privacy and automated-scanner limits;
- negative-mutation regression posture; and
- current modern-CSS problem-fit dispositions with a refresh route.

### `context-canvas-surface-reading`

One rule now separates document meaning, accessibility-tree or DOM representation, rendered visibility, geometry, and screenshot content. Benchmark architecture supplies hypotheses. A local task supplies behavior evidence before an AI-visitor claim travels further.

## Public skill billets

### `semantic-information-surface-authoring`

- **Receiving job:** Shape content-led explanatory pages whose hierarchy, measure, grouping, headings, link information scent, and reading rhythm need a coherent authoring intervention.
- **Current contribution:** Reading comfort, scanning variation, and visitor commitment now have a source-supported evidence boundary.
- **Adjacent owners:** Surface reading, supportive writing, CSS ownership, and the existing reading-measure research.
- **Forge condition:** Two materially different authoring or refactor tasks show a distinct intervention beyond those owners; at least one supplies human reading or task-completion evidence.
- **Current route:** `queue_with_trigger` through milestone-22 issue #150.

An `attention-ergonomics` interpretive lens can foreground fatigue, crowding, commitment, information scent, and scanning variation during that issue. It remains non-routable and exits with the task unless an independent result appears.

### `agent-observation-channel-agreement`

- **What:** Map one browser task across semantic/accessibility, DOM geometry, and rendered screenshot channels.
- **When:** Browser-agent interpretation or an accessibility-to-agent claim depends on the channels agreeing.
- **Boundaries:** Benchmark architecture does not establish local task performance. Human accessibility retains independent value. Model and platform facts require current evidence.
- **Result:** A task-bound agreement/divergence map, smallest repair owner, and explicit generalization limit.
- **Forge condition:** One real repository task runs through an AX/DOM-style observation and a screenshot/VLM-style observation, and the divergence changes a decision beyond surface reading plus a practitioner probe.
- **Current route:** `queue_with_trigger` through milestone-22 issue #149.

### `surface-color-state-stewardship`

- **Receiving job:** Carry a painted-owner foreground contract across a visitor system outside Context Canvas.
- **Current evidence:** The role architecture is exercised once and is documented in a Context Canvas-specific owner.
- **Forge condition:** A second non-Canvas system needs the same role/state/mode matrix and exposes a decision not already carried by its CSS owner or visual-verification route.
- **Current route:** `observe` in the public plan; no active catalog entry.
