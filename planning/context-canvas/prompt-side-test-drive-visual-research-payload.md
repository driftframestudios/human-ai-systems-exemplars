## §A — Decision frame

### Receiving decision

Design a visitor flow and explanatory system map that let a first-time visitor:

- understand one consequential prompt-side condition quickly;
- test that condition in a real interactive surface before reading the complete method;
- see which choices changed the working prompt capsule;
- recover source standing, task position, uncertainty, human authority, and the revision route;
- continue into deeper reference material without losing the experiential thread.

### Approved page route

The visitor receives two reading layers.

#### Test-drive layer

1. **Hero and short quick route** — explain that the page builds a working prompt capsule.
2. **I. Resolve the human reference when it can change the work** — retain the three request-comparison cards and orientation note as the concise lead-in.
3. **II. Test-drive the Open Lesson Field** — let the visitor move real conditions, inspect consequences, and read a post-lab change receipt.

#### Method layer

4. **III. Read the collaboration system behind the working capsule** — place the accessible SVG and nine-move semantic table after the lab, followed by deeper reference, register, social-proxy, persona, and benchmark material.
5. **IV. Name the state the result should create.**
6. **V. Compose the smallest packet that can change the decision.**
7. **VI. Compare the option space before committing.**
8. **VII. Apply it this week.**
9. **Evidence Boundary and source register.**

### Design question

How can the system map explain the collaboration a visitor has just experienced while remaining lighter than dense documentation, accurate enough for engineering review, and useful at narrow viewport widths?

### Stable visitor promise

> Begin with one consequential human reference, test-drive the working prompt capsule, then inspect the deeper collaboration system and its evidence boundary.

## §C — Method spine

### C1. Start with the receiving task

The first visitor task is experiential: recognize an open task position, enter the lab, change one work-bearing condition, and inspect the receipt. The system map explains that experience afterward.

### C2. Preserve five distinct condition types

1. **Task position** — named human role, group, artifact user, or receiver.
2. **Source standing** — provenance, trust, analytic role, and quoted-command boundary.
3. **Working transformation** — analysis, extraction, classification, summarization, drafting, or execution.
4. **Candidate field** — multiple plausible routes with assumptions and route-changing observations.
5. **Human return** — the person or role able to inspect, authorize, revise, or recover the next decision.

### C3. Use positive-state language with explicit material boundaries

Describe the state the collaboration should create: calm, specific, inspectable, revisable, evidence-bounded, and recoverable. Keep privacy, authorization, source, safety, factual, and scope boundaries explicit beside the usable replacement state.

Examples:

- **Stable direction:** “The task role and receiving educator are explicit.”
- **Material boundary plus usable state:** “Learner identities remain in approved school systems; use the class-level coordination conditions supplied in the fixture.”
- **Recoverable handoff:** “The reviewed capsule names its sources, assumptions, candidate route, receiver, and next evidence check.”

### C4. Make class-level scale causally legible

“28 learners” becomes useful when it changes visible coordination work. The prototype may trace the count into grouping, materials, participation, reporting time, rotating roles, technology arrangement, educator movement, evidence collection, room configuration, and accessibility review.

The count remains a class-level planning condition. It supplies no identities, individual profiles, disability records, family context, behavior labels, or conclusion about pedagogical fit.

One worked causal chain is:

> 28 learners → 14 pairs → 14 material sets → paired comparison → 28 individual evidence-boundary notes → educator review

Alternative grouping routes stay visible for educator selection. A Verbalized Sampling frame can ask an approved AI collaborator to generate a bounded set of materially distinct coordination responses, assign each a probability relative to the full response distribution, and disclose residual mass held by unlisted responses. A separate optional frame can compare the three authored lesson routes under the currently selected grouping against one precisely stated event. Any returned candidate probabilities or conditional event estimates remain model-elicited planning material pending local educator observation.

### C5. Keep equal conditions visibly equal

Source labels, reference anchors, desired state, transformation, purpose, encoded-material inspection, output review, and human return support one another. Numerals may orient the reader, while weight, size, color, and position avoid creating an unearned rank.

### C6. Preserve the non-JavaScript and text routes

The diagram is an explanatory enhancement. The HTML semantic table is the durable operating record. The Open Lesson Field has a complete static equivalent. Native source order, fragments, captions, print, and meaningful no-script content remain authoritative.

## §D — Four visual hypotheses

Each hypothesis must use the same concept ledger and be evaluated against the same visitor task.

### D1. Butterfly field

**Composition:** intake conditions form a left wing; receiving and review conditions form a right wing; the working prompt capsule is the thorax.

**Useful move:** makes before/after and source/receiver relationships immediately scannable.

**Design risk:** bilateral symmetry can imply that source authority and receiver authority are interchangeable. A simple butterfly also underrepresents revision.

**Question to test:** can a reader find the central packet, entry field, and human receiver before reading node copy?

### D2. Inverted radial journey

**Composition:** equal conditions orbit a central prompt capsule, with a deliberate opening at the human return.

**Useful move:** reduces ordinal hierarchy and creates a compact, generative form.

**Design risk:** a circle can imply automatic completion, repeated inevitability, or equal causal contribution. Text-heavy nodes become small at narrow widths.

**Question to test:** can the open return path remain clear while each node retains a useful label at 390 CSS pixels?

### D3. Closed-loop service blueprint

**Composition:** stages travel horizontally while human collaboration, artifact, model/tool, and evidence/authority occupy distinct lanes; review returns to the smallest field that needs revision.

**Useful move:** gives roles, handoffs, backstage work, source standing, and review gates their own visible places.

**Design risk:** a complete blueprint can resemble the dense documentation the page now deliberately places after the lab.

**Question to test:** can four lanes remain visible while node prose moves into the semantic table?

### D4. Full product-service system loop

**Composition:** actors, artifacts, services, evidence sources, boundaries, candidate routes, recovery, and outcomes form a complete ecosystem loop.

**Useful move:** carries the richest systems truth and makes dependencies explicit.

**Design risk:** atlas-scale completeness can displace the page’s practice-guide purpose and make the working capsule harder to find.

**Question to test:** which relationships can move into the table or research payload while the visual keeps its explanatory center?

### Comparative reading

| Criterion | Butterfly | Inverted radial | Closed-loop blueprint | Product-service loop |
| --- | --- | --- | --- | --- |
| Central packet visibility | Strong | Strong | Moderate | Moderate |
| Source-to-receiver scan | Strong | Moderate | Strong | Strong |
| Human/model/artifact distinction | Moderate | Moderate | Strong | Strong |
| Revision path | Weak without an added rail | Moderate | Strong | Strong |
| Narrow-width resilience | Moderate | Moderate-to-weak | Moderate with stacked lanes | Weak without major simplification |
| Risk of documentation density | Low | Moderate | High | Highest |
| Best contribution to synthesis | Paired fields | Equal-weight orbit | Lanes and return | Whole-system coverage ledger |

## §E — Selected synthesis: Butterfly Service Loop

### E1. Visual proposition

**Working title:** *Prompt Collaboration Service Loop — a working capsule moves from field conditions to reviewed human use*

Combine the butterfly’s immediate paired-field scan with the service blueprint’s distinct lanes and a clear evidence-return rail.

### E2. Geometry

- **Center:** Working Prompt Capsule.
- **Left intake field:** task and object, source standing, useful exposure, consequential reference.
- **Right receiving field:** candidate routes, generated artifact, named receiver, review receipt.
- **Top arc:** desired state → authorized transformation → candidate generation.
- **Bottom return rail:** review observation → evidence boundary → smallest useful revision → restored working capsule.

### E3. Service lanes

1. **Human collaboration** — requester/task position → educator or accountable reviewer.
2. **Artifact and packet** — source packet → working capsule → reviewed handoff.
3. **Model/tool participation** — bounded transformation and candidate generation.
4. **Evidence and authority** — provenance → boundary → review → revision receipt.

### E4. Central packet fields

The central capsule can expose a concise set of typed modules:

- desired state;
- task object and transformation;
- evidence horizon and source labels;
- uncertainty;
- consequential referents;
- register and disclosed social proxy;
- privacy, authorization, factual, and scope boundaries;
- output shape;
- named human receiver.

### E5. Semantic node ledger

Every visible region receives:

- a stable, human-readable SVG `id`;
- a local `<title>` and, where useful, `<desc>`;
- a semantic `<g>` grouping;
- a concise visible label;
- a matching row or phrase in the HTML semantic equivalent;
- an explicit relationship to entry, capsule, candidate, receiver, or return.

### E6. Narrow composition

At narrow widths, the map preserves five visually recoverable regions on a locally scrollable engineering sheet rendered at a working label size:

1. intake field;
2. working capsule;
3. receiving field;
4. evidence boundary;
5. return route.

The sheet keeps a 90rem working width until the viewport can carry the complete composition, while its labelled scroll region contains movement within the figure. Node descriptions move to the adjacent HTML table instead of being compressed into miniature SVG copy. The full-size link continues to open in a new tab and says so on the surface.

### E7. Motion boundary

An optional attention trace may move through intake → capsule → candidate field → receiver → revision. The complete system remains visible at rest. Reduced motion preserves the final static state, and meaning remains available without animation.

## §I — Worked micro-example: 28 learners

### Starting request

> Draft a Grade 9 statistics lesson plan for an educator teaching 28 students.

### Resolved task position

- **Requester/task position:** classroom educator preparing a draft.
- **Receiving human:** classroom educator, with curriculum lead and data-literate reviewer available for named checks.
- **Desired state:** a calm, specific, time-bounded lesson draft with observable learner evidence and explicit source roles.
- **Hard boundary:** class-level planning conditions may shape coordination; individual learner records remain in approved systems.

### Candidate grouping field

| Route | Coordination consequence | Key assumption | Route-changing observation |
| --- | --- | --- | --- |
| 14 pairs | 14 material sets; paired comparison; individual evidence note from each learner | Pair discussion supports active participation | Several learners need a more explicit role structure |
| 8 trios plus 2 pairs | 10 material sets; two- or three-role turn structure; individual evidence note from each learner | Small peer teams make multiple comparison turns workable | Reporting or role rotation needs a clearer route for the two mixed-size teams |
| 7 groups of four | 7 group packets; rotating roles; group claim plus individual reflection | Four named roles distribute the work | Each learner needs a more explicit turn-taking or role-rotation path |

### Two probability frames: generated fan-out and authored-route event assessment

**Frame A · Verbalized Sampling generated set**

```text
Planning question: Given this Grade 9 lesson capsule, what distinct
coordination plan could help 28 learners produce one interpretable
evidence-boundary note within 55 minutes?

Within one response, generate exactly five distinct candidate answers. Give
each a stable label, coordination plan, assumptions, and evidence that would
change it. Assign every candidate a probability expressed as a percentage
from 0% to 100% relative to the full distribution of plausible responses.
Report the listed probability mass and the residual or unlisted response mass
that completes the full distribution. The five listed candidates may carry
less than 100% of the mass; the residual keeps wider alternatives visible.
```

**Frame B · Optional authored-route event assessment**

```text
Named binary event: In the 55-minute Grade 9 session, the route enables all
28 learners to produce one interpretable evidence-boundary note from the
invented watershed fixture under educator review.

For each authored lesson route—Plot and annotate, Lag and compare, and Claim
and challenge—use a fresh assessment pass under the selected grouping and estimate
P(named event | route, shared conditions). State the rationale, coordination
dependencies, and evidence that would most change the estimate. Each value is
an independent conditional estimate rather than a share of a three-route
distribution. Full-response probability mass and residual accounting remain
with the generated Verbalized Sampling set in Frame A.
```

The repository-local lab populates both frames with the current shared conditions while leaving candidate answers and probability values open. It keeps the method distinction and fields inspectable for a separately authorized AI-enabled workflow and receiving-educator review. Local rehearsal and classroom observation provide the evidence that changes the route.

### Visual trace

The Butterfly Service Loop should make this micro-example traceable without turning it into a mandated plan:

> class-level condition → candidate grouping field → working capsule → educator review → observed participation evidence → smallest useful revision

## §K — Open questions and route-changing observations

1. Does the central capsule remain visually dominant without appearing to outrank the human receiver or evidence boundary?
2. Can the four service lanes remain legible at narrow widths, or should the narrow SVG switch to five stacked regions connected by one return rail?
3. Should the nine sanitation moves remain visibly numbered inside the synthesis, or should numerals live in the semantic table while the SVG uses named clusters?
4. Which source-standing distinctions earn visible nodes, and which remain table-level detail?
5. Does a lower evidence-return rail communicate revision clearly enough without implying a deterministic cycle?
6. Can the class-size causal trace appear as a worked inset without making 28 the normative class size?
7. Should the candidate grouping field appear in the parent page, the embedded lab, or both with distinct purposes?
8. Which animation, if any, materially improves relationship comprehension over the static map?
9. Does the selected geometry preserve the approved ruled paper, clipped corners, offset shadows, Cobalt, Tiffany/sea-glass, lime, and rose treatments without visual overload?
10. Which browser-harness assertions can verify semantic coverage and source order without coupling tests to decorative markup?

A route-changing observation should be concrete. Examples include: the central capsule is not found first in a five-second scan; a narrow render requires text below the current readable threshold; the human receiver appears subordinate to model generation; a semantic-table row has no visual or documented deferral; or the return rail reads as automatic approval. Record the observation, smallest useful revision, and receiving reviewer.
