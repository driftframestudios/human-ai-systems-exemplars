# Table-audit campaign receivers

This layer binds the draft to the existing table-repair work. It supplies local
owners and interpretation cues while the root contract remains transferable.

## Source and evidence owners

- PR #326 and Issue #329 own the bounded application adapter, deterministic invalidation and campaign publication.
- Issues #319 and #320 retain the application campaign and research receiving roles.
- [Table reading contracts](../../../../../../tests/tables/README.md) own current local commands and browser/material behavior boundaries.
- [Review-wave exercises](../../review-wave-exercises.md) carry the boundary deck and recorded returns. Their counts belong to the named observations, including the distinction between fresh records and unchanged reuse.

## Conditional repair routes

| Trigger | Local receiving distinction |
| --- | --- |
| A loaded dependency or assertion input changes | Follow its existing helper/data/style owner and reopen dependent cases; a matching old key describes its former closure. |
| Broad text agreement hides a wrong record or missing interaction | Exact-record identity, inspector visibility and the corresponding state transition receive their own assertions. |
| Concurrent snapshot requests or interrupted screenshot publication | Shared pending capture, retry ownership, complete artifacts and publication of a generation remain separate boundaries. |
| A campaign resumes with matching accepted records | Reuse establishes the recorded recovery behavior; comparisons about saved work retain the research receiver. |

The existing fixture, focused campaign, unchanged-resume and material-behavior
returns support their declared boundaries. Their current results remain in the
exercise record and application return rather than a second mutable scoreboard.
A unit result, a browser observation and a reviewed receiving decision have
distinct roles.

## Authority and release

Local evidence publication belongs to the authorized application contract.
Hosted publication, a generalized artifact store, broader runtime architecture
and predictive scheduling retain their separate decisions; the draft supplies
neither a new execution request nor a promotion gate. The local binding releases
when the parent accepts the bounded return or names the remaining observation.
A new dependency, counterexample or materially different receiving task can
reopen the portable contract.
