# Responsive raster publication

## Contract

- **What:** A source-owned raster family whose candidate widths, slot contract,
  intrinsic geometry, accessibility text, metadata standing, and public route
  remain coherent.
- **When:** Repository markup owns a responsive content-image slot or a measured
  comparison must decide between authored candidates and Cloudflare edge
  transformation.
- **Boundaries:** SVG, fixed metadata images, CSS backgrounds, art-directed
  crops, third-party rights, and public activation retain distinct fitting owners.
  Credential scanning, embedded-metadata inspection, and human rights review
  remain distinct claims.
- **Result:** One named delivery owner, a reproducible source-or-smaller candidate
  family, an accurate `srcset`/`sizes` contract or bounded edge alternative,
  semantic inventory lineage, and representative browser observations.

## Rules

### Rule: The page describes the slot

Measured layout slots determine candidate widths and `sizes`. Each `w`
descriptor equals the candidate's intrinsic pixel width. Intrinsic `width` and
`height` reserve geometry before transfer.

### Rule: Candidate families stay finite

A small set covers observed slots and useful density ranges. Derivative
generation preserves aspect ratio, keeps source-or-smaller geometry, writes atomically, and
supports a non-mutating check.

### Rule: One selection owner leads

Authored `srcset`/`sizes` leads where markup owns the slot. Cloudflare
transformation enters through a disjoint canary when stable unchanged markup
creates a demonstrated need. One asset family carries one active responsive
selection owner after comparison.

Cloudflare Image Transformation Flows provide the current unchanged-URL edge
comparison. A `width=auto` canary uses delegated viewport-width and DPR hints,
then Cloudflare's documented user-agent fallback; the result approximates a
viewport class rather than measuring the image's actual CSS slot. Bounded
breakpoints, transformation cardinality, cache behavior, and source-owned
fallbacks remain part of that comparison.

### Rule: Semantics travel from the source owner

Alternative text, captions, source identity, profile, dimensions, media type,
digest, consumers, public projections, and recovery source remain linked in
the semantic asset inventory.

### Rule: Publication boundaries stay distinct

The exact candidate closure receives a canary-proven credential scan, a
format-aware metadata observation, and a human rights/consent decision. Each
boundary returns its own scope, disposition, and unresolved findings while the
other claims retain their fitting owners.

## Operating sequence

1. Bind source revision, canonical asset, consumers, intended route, and Issue.
2. Measure the actual slot at representative narrow, medium, desktop, and wide
   viewports.
3. Select content, art-direction, CSS-background, fixed, SVG, motion,
   source-master, excluded, or retired standing.
4. Choose a finite source-owned candidate family or a bounded edge canary.
5. Generate derivatives through the repository owner at source-or-smaller size,
   atomic replacement, exact dimensions, media types, profiles, and digests.
6. Inspect credential-shaped material, embedded metadata, visible content,
   attribution, rights, and consent through distinct owners.
7. Update semantic inventory and production selection together.
8. Observe requested URL, encoded and decoded dimensions, transfer size, slot,
   DPR, sharpness, crop, color, text legibility, layout reservation, loading,
   cache behavior, print, forced colors, and scriptless fallback.
9. Return the accepted owner, family, route behavior, and recovery source.

## Completion

The skill candidate settles when repeated image work demonstrates reliable
routing, source-owned generation, metadata and rights separation, accurate
browser selection, and a smaller decision burden than direct application of
Issue #286 and the existing asset inventory.
