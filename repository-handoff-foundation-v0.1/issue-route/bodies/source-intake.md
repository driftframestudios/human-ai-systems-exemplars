## Outcome

Receive and characterize the actual site source so its own structure and
behavior can choose the repository's technology route.

## Why this matters

The repository already provides a neutral collaboration frame. Source intake
turns that frame into evidence: the runtime, package manager, lockfile, routes,
assets, visual direction, external services, and reproducible commands become
observable before application tooling is selected.

## Work

- Record the source origin, observation date or revision, and relationship to
  the future maintained source.
- Distinguish editable source from generated output.
- Inventory routes, assets, styles, fonts, manifests, runtime, package
  manager, lockfile, and declared scripts.
- Identify declared environment-variable names, external requests, forms,
  storage, authentication, analytics, and hosting metadata. Secret values stay
  in their authorized systems.
- Record collisions with foundation files and preserve both inputs for a
  reviewed decision.
- Establish a clean preview or build command when the source supports one.
- Capture representative narrow and desktop states when browser observation
  is available.
- Record the observed facts that should guide later lint, test, dependency,
  accessibility, browser, and deployment work.

## Handback

Return the inspected coordinate, the bounded source and technology profile,
the observation that establishes reproducibility, its coverage boundary, and
the next foundation-reconciliation action. Source acceptance remains with the
preparing owner.
