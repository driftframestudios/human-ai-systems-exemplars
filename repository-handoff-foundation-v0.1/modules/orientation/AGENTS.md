# Repository collaboration ground

This repository supports continuing ownership through current source,
plain-language GitHub Issues, and reviewable evidence. Keep process
proportional to the behavior being changed.

## Begin with current truth

- Confirm the current branch, revision, worktree state, recent history, and
  active Issue or pull request before acting.
- Read the root and nearest README plus every source owner that materially
  shapes the requested behavior.
- Treat runnable source and artifacts as behavior authority. Use Issues for
  current outcomes and acceptance, `planning/concept-nursery/` for resting
  possibilities, and `threadkeeping/` for settled rationale and re-entry.
- Preserve unrelated work already present. Name a difference when a prior
  record and current source disagree, then continue from current source.

## Let received source choose the technology route

Inspect the site's runtime, package manager, lockfile, routes, assets, styles,
fonts, external requests, forms, storage, authentication, analytics, hosting
metadata, and reproducible commands before selecting application tooling.
Preserve incoming structure, visual direction, notices, package manager, and
lockfile. Route collisions through the source-intake Issue for review.

## Work through one live Issue

Each active Issue names one outcome, its acceptance signals, related work,
authority boundaries, and next receiver. Make the current front easy to find.
When a separate outcome appears, prepare a connected Issue so the accepted
contract keeps its current scope.

Live Issues become current authority after materialization. The semantic seed
remains a bootstrap, comparison, and recovery input.

## Keep held decisions actionable

Identity, rights, credentials, visibility, transfer acceptance, publication,
domains, and destructive recovery remain with their named human owners. Pair
each held boundary with the preparation that remains available and the exact
event or decision that releases continuation.

## Keep evidence useful

Choose the smallest observation that answers the current question. State what
the observation establishes before its coverage boundary. Keep credentials,
raw logs, private routes, account-held values, and query-bearing URLs with
their access-controlled owners; return a concise condition and continuation
on public-possible surfaces.

End a cycle with the changed surface, exact validation and normalized result,
environment note, current Issue or pull request, next receiver, and one exact
re-entry action.
