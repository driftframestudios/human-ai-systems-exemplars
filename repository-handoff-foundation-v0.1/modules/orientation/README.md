# Repository orientation

This repository is ready to receive site source while its future owner and an
authorized AI collaborator work through plain-language GitHub Issues. The
current Issue supplies the next outcome. Received source supplies the runtime,
package manager, lockfile, routes, visual direction, and application behavior.

## Begin here

1. Read the current GitHub Issue, its milestone, related Issues, acceptance
   signals, and next receiver.
2. Confirm the branch, revision, worktree state, and recent history.
3. Read `AGENTS.md` and the nearest README for the source area in scope.
4. When site source arrives, inventory it before selecting application
   packages, build tools, or framework-specific checks.
5. Return one reviewable result with the evidence it establishes, its coverage
   boundary, and the next owner action.

The source-intake Issue remains the current front while the application stack
is unknown. Foundation work can prepare orientation, references, resting
concepts, and re-entry records while technology selection waits for source
evidence.

## Working map

| Surface | What it carries |

## Owner-held decisions

Identity, rights, credentials, repository visibility, transfer acceptance,
publication, domains, and destructive recovery stay with their named human
owners. Repository work can prepare the evidence and exact next action each
owner needs. Account-held values remain in their authorized systems.

## Ordinary collaboration request

Once the Issue route exists, this request is enough to begin a normal cycle:

> Create a detailed Issue for the outcome, connect it to the current milestone
> and related Issues, then travel the active Issue route. Explain what each
> move makes possible and return any decision that needs my account authority
> or judgment.

The collaborator still reads current source, repository instructions, and
live Issue state before acting. The request supplies intent; the current task
grant supplies authority for repository or external changes.

## Evidence and continuation

A structural check establishes the files, digests, and relationships it
actually inspects. Source-native checks establish only the application
behavior they exercise. Transfer, publication, and continuing usefulness
retain their human or receiving-collaboration owners.

Close each cycle with the changed surface, the exact check or source
observation and normalized result, the state it establishes, the adjacent
claim still open, and one precise re-entry action.
