## Decision

The repository now carries a small, repository-local collaboration layer:

- root `AGENTS.md` supplies standing ground that benefits nearly every turn;
- nine instruction-only portable skill contracts under `.agents/skills/` supply standing on-demand workflows;
- the task-bound CSS and schema projections have retired after returning their decision-changing observations upstream;
- existing READMEs, Visual Fidelity Contracts, tone goals, planning, and threadkeeping remain the detailed source authorities;
- scripts, UI metadata, plugins, routers, and evaluation harnesses return when repeated use demonstrates a concrete need.

The initial skills are `repository-reentry`, `context-canvas-surface-reading`, `context-canvas-css-ownership`, `practitioner-probe`, `supportive-change-writing`, `evidence-grounded-research-spike`, `declarative-skill-authoring`, and `collaboration-accounting`.

Material schema work later added `schema-contract-authoring` as the ninth portable contract. Its `prototype-exemplars-schema-v1-projection` derivative served the schema-root, adjacent-family, page-migration, and operator-host waves, then left active routing after publication and the operator-host handoff settled its exit event.

## Why this shape fits

Official contemporary skill guidance and practiced expert corpora converge on progressive disclosure, distinct description-based routing, one coherent outcome, explicit completion, and instruction-first design. The repository's own collaboration history supplies the local jobs: rebuilding current truth, reading pages as design input, tracing CSS ownership, forming strong technical probes, writing supportive change language, and precipitating research into a decision.

This form carries vocabulary without introducing a parallel operating system. Git versions each skill beside the work it supports. A collaborator can inspect the exact instruction, follow its repository sources, and revise it through the same review path as other guidance.

## Declarative specification boundary

Each skill now opens with What, When, Boundaries, and Result; names invariants as rules; retains an action-bearing sequence when order matters; and uses sparse Given/When/Then scenarios only where an ordinary behavior or consequential boundary would otherwise remain ambiguous. Uncommon source-specific scenarios move into directly linked references. Scenario prose remains illustrative until an implemented test, script, or step definition explicitly makes it executable.

Skill descriptions and bodies use third-person, artifact- and role-centered language. The supportive-change register and Semantic Attractor Design shape the prose: desired state leads, evidence remains calibrated, authority stays visible, and each boundary carries a workable route forward.

The Enterprise Human-AI Practitioner Registry supplies practiced possibilities and research lineage rather than a personal model. Skill names describe transferable affordances; source-specific observations retain provenance and transfer limits. Each initial skill attempt is successful evidence in a repository that previously had no skill corpus.

Skill form can vary with the problem terrain. Deterministic mechanics fit compact procedures or later scripts. Systemic and evolving work can require probes, scenario bridges, option surfaces, attention structures, and return conditions. In that terrain, completion names a useful bounded intervention and a durable route back rather than implying that every connected consequence has reached final resolution.

Failure Geometries and Recovery Routing complete that posture without adding an active skill. A recurring strain is treated as an observable collaboration or system shape. Gap utility precedes repair; useful gaps can remain open; consequential gaps receive the smallest adequate move routed to the owning surface; remaining dimensions stay visible. The active Probe, CSS, research, writing, and skill-authoring instructions carry this connection in proportion to their jobs.

## Accretive stewardship boundary

`collaboration-accounting` is the first skill formed through the active skill corpus itself. A varied second Notion sampling pass and a six-database metadata sweep supported immediate creation: the receiving job is live, no active skill owns the lifecycle decision, the first version is inexpensive to revise, and explicit experimentation trust makes first use valuable evidence.

The skill separates creation, one-use usefulness, promotion, and stabilization. It gives a decision-changing observation six possible routes: create, iterate, queue with a trigger, observe, settle or fold, and merge or retire. One primary route and one smallest action close the pass. Another pass begins when new evidence, intent, dependency state, authority, or observed behavior could change the decision.

Probability ranges remain optional planning priors with a named referent. The sampled Notion corpora are living and incomplete, so they supply vocabulary, contrasting structures, and field evidence rather than statistical fit. A compact reference preserves the deeper candidacy model while ordinary activation remains short.

The next natural use extended this stewardship boundary through a contract-first projection model. A portable skill contract keeps durable authority. A task-bound skill projection binds selected behavior to a named task, tool surface, authority scope, lifetime, and exit event. A non-routable context capsule carries deeper local selection when automatic routing has no clear turn-economy benefit.

Routable projection depth is capped at one. Further task-local detail remains a capsule, account, or upstream proposal; a distinct transferable job returns through `create_now` as a new portable contract at depth zero. This depth marker controls recursion alone while usefulness, maturity, authority, lifetime, and disposition remain independent.

`context-canvas-ai-systems-css-projection` was the first temporary projection. Its thirteen-route CSS extraction settled in its receiving merge, its file-boundary and computed-cascade observations returned to the portable contract, and the declared re-entry exit event selected retirement. `prototype-exemplars-schema-v1-projection` followed the same route after the public mirror, page graph migration, and explicit operator-host handoff exposed its final portable rules.

## Practitioner Probe boundary

The Notion Practitioner Probes system contributed a lean anatomy:

1. question;
2. affected actor and why the question matters;
3. technical or organizational mechanism;
4. observable evidence;
5. instruction yield.

Source confidence and transfer limits appear when they affect the decision. Scoring, levels, probability models, registry apparatus, and machine-node taxonomies remain optional research context. The repository skill is useful when a concern is ambiguous or code appears plausible but shallow. A direct, already-scoped repair can proceed through its owning workflow.

## Deep-research boundary

The research-spike skill begins with a receiving decision, uses primary and official sources for current technical facts, distinguishes verified fact from inference, practitioner observation, and open hypothesis, seeks disconfirming conditions, and stops when further evidence no longer changes the next move.

Notion remains hydration material rather than a repository dependency. The durable instruction is carried locally, and direct source routes remain in the planning surface for future review.
