## Working moment

Issue #13 reopened the assembled successor as its own source of authority. The
initial population audit named 43 machine-reference values across 24 files.
Population pull request #15 had already settled most of those values by the time
the focused implementation began. Thirteen current-successor references still
bound Collaboration Skills examples to GitHub's `main` branch, while package and
secret-boundary tooling still spoke as the retained repository.

The settlement converts those thirteen source-tree references to
repository-root-relative paths. Hosted `schemas.vik.guru` identities continue to
name delivery, and the existing source files continue to name meaning. The
repository schema command now compiles both Collaboration Skills schemas,
validates all three examples, and affirms that their local references resolve.

## Identity decisions

Current operational ownership now names Human-AI Systems Exemplars in package
metadata, Betterleaks installer identity, scanner receipts, and the scanner skill's
repository-specific context. The following identities retain their established
meaning:

- exact-version schema `$id` values and `schemas.vik.guru` delivery identities;
- `urn:source-key:prototype-exemplars` as a stable relation to the retained source;
- Prototype Exemplars schema-family names;
- A3 source provenance; and
- LIMS/ELN seed and finding ancestry.

Collaboration Skills remains at `0.1.0`. This is a pre-publication locator
settlement: the represented contract and validation meaning remain stable, so a
new exact-version directory would add identity without adding meaning.

## Affordance return

`source-authority-mapping` and `locator-boundary-stewardship` carried the useful
distinction between semantic ownership, source-tree location, hosted delivery,
and retained lineage. The material implementation also sharpened one boundary:
a branch-bound link to the current repository is a delivery-shaped locator where
a repository-relative reference provides the more durable exchange value.

The earlier Spark preflight supplied a successful hosted and local behavior
receipt, then continued from observation into repair. That outcome becomes a
routing observation for `bounded-support-routing`: a future support packet names
`observation_only` or `repair_authorized`, its stop condition, and its natural
return so the supporting collaborator can contribute at the intended boundary.

## Return condition

Return when operator-host delivery settles, a machine consumer requires a new
locator form, or an independently observed receiver cannot reconstruct source,
meaning, lineage, and delivery from the current references. Until then, the
existing schema command and ordinary repository review carry the settled route.
