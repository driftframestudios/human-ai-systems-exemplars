## Working moment

The repository needed an expressive schema surface before public serving architecture settled. The receiving work joined several concerns that are easy to blur: repository orientation, Context Canvas designed experience, existing Supportive Change Writing and LIMS/ELN contracts, two future retrieval hosts, and a request for schema guidance that other hybrid teams could reuse.

The material boundary was narrow enough to remain observable. Two authored v1 contracts, four external examples, one JSON-LD context, and two existing-family uses could test the central distinctions without forming a schema registry or a second operating system.

## Skill formation and effect

`collaboration-accounting` routed the reusable job through `create_now`. The job had an active receiving surface, no existing skill owned schema identity and dependency questions together, and an instruction-only contract was inexpensive to revise. `declarative-skill-authoring` supplied the What/When/Boundaries contract, rule declarations, sparse scenarios, and progressive disclosure shape.

The resulting `schema-contract-authoring` skill changed the implementation in several visible ways:

- the repository root became an orientation contract rather than a universal artifact ontology;
- Context Canvas received its own contract for designed experience, standing, authority, representations, relations, contracts, and recovery;
- canonical identity, repository location, public retrieval preference, semantic ownership, instance ownership, and publication authority stayed separate;
- Supportive Change Writing and LIMS/ELN remained linked projections with their source contracts and dependency behavior intact;
- external examples became first-class collaboration material instead of schema annotations alone;
- one namespaced extension seam preserved experimentation while concrete shared objects remained dependable.

The task-bound `prototype-exemplars-schema-v1-projection` kept issues work:schema-authority, work:prototype-exemplars-schema-root, work:schema-semantic-settlement, and work:schema-retrieval-and-page-migration, the dual-host model, and the human publication cue close to the active work. Its depth-one bound held local decisions in one projection, returned durable rules to the portable contract, and supplied an explicit exit rather than becoming standing architecture.

## Research movement

The deep-research spike used three evidence lanes: Draft 2020-12 and validator documentation, empirical public-schema defect research, and practiced schema-evolution guidance. The strongest changes were direct:

- one absolute fragment-free `$id` now remains invariant across source and future mirrors;
- exact-version bytes gain immutability after publication;
- local `#/$defs/...` pointers keep v1 self-contained;
- each enum receives treatment as a compatibility commitment;
- `format` remains an explicit annotation posture in the current validator;
- external examples receive direct validation while default insertion, coercion, and property removal remain disabled;
- generated schemas require a named validation, serialization, or other projection mode;
- automated compatibility analysis waits for a second version or a real receiving consumer.

The empirical corpus strengthened strict compilation as a useful barbell endpoint: a small command catches malformed schemas and real-instance incompatibility while the human-readable plan and examples carry most of the meaning. The historical and generated composition of that corpus limits any prevalence claim, so the account transfers defect categories rather than defect rates.

## First-use corrections

The first strict compilation immediately supplied two useful observations. Private named anchors added indirection without a public reference use and interacted poorly with the selected strict validator. Local JSON Pointers expressed the actual boundary more directly. A conditional requirement for provisional projections also needed to declare its participating properties inside the conditional branch for strict compilation to remain legible.

Those observations routed through `iterate_now`. The portable skill now prefers flat descriptive definitions and private JSON Pointers, reserves public anchors for an actual relocatable receiving use, distinguishes `$schema`, `$id`, and instance version conventions, names exact-version immutability, treats enums as compatibility commitments, requires generated projection modes, and makes non-mutating validator policy explicit.

The local check then passed across both strict v1 schemas, four v1 instances, the existing Supportive Change Writing manifest, the native LIMS/ELN machine-node use and dependency closure, and three consequential boundary probes. Its output remains one terminal line. No generated receipt, hosted gate, hash catalog, or compatibility matrix formed around the result.

Issue work:schema-semantic-settlement supplied a second material use before exact-version publication. ## Third material use — publication and page graph migration

Issue work:schema-retrieval-and-page-migration supplied the projection's exit use. The Radiant Null exact-version mirror became active, HTTPS-enforced, and observable against the released repository bytes. Current authoritative observation found the intended Vik Guru retrieval host absent from DNS. Canonical identity therefore stayed stable while retrieval availability moved into an explicit operator handoff; the published schema and context bytes remained unchanged.

Seven legacy pages then exercised the semantic context directly. The migration exposed one portable graph distinction: a page topic can be a real `DefinedTerm` without becoming a member of the Context Canvas predicate vocabulary. Topical subjects now remain mentions, while only terms actually defined by the context belong to its `DefinedTermSet`. Unsupported fragment references also resolved to declared resource identifiers, and each graph keeps canonical identity separate from the active retrieval URL.

This observation routed through `iterate_now` to `schema-contract-authoring`, which now asks semantic relationships to remain literal. The local projection carried no further unique job after the page graphs, mirror observation, and operator handoff settled. Collaboration accounting therefore selected `merge_or_retire`: active routing leaves the catalog, while Git history, this account, and issue work:schema-retrieval-and-page-migration preserve the receiving context.

## Present limits

These are three related material uses of a new skill within one schema tranche. They establish instruction yield and expose useful friction; wider effectiveness remains open. AI findability through descriptive names, adjacent READMEs, examples, and progressive routes remains a repository hypothesis awaiting ordinary re-entry by later collaborators.

The JSON-LD context now has seven page-level graph uses, while no external consumer has yet expanded or queried those graphs. Radiant Null provides the observed exact-version retrieval route. Vik Guru restoration, TLS, and byte parity remain an external issue work:schema-retrieval-and-page-migration handoff. Compatibility automation has no version relationship to inspect yet.

These limits leave the portable skill appropriately provisional. Another skill or validator layer would add little at this moment. Natural review, cross-repository use, and a later additive schema revision provide higher-value tests.

## Re-entry

Return after pull-request review changes a schema distinction, a cold collaborator encounters a discovery or naming gap, another repository projects the contract, or an additive schema version introduces a compatibility decision. A fresh task-bound projection forms only when that receiving task benefits from temporary bindings; host-specific restoration remains in the publication issue.
