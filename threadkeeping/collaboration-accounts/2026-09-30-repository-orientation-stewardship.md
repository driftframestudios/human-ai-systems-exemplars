## Working observation

A source-grounded audit followed root and nested README routes across Human–AI
Systems Exemplars, Gist Registry, and the five LIMS/ELN repositories. The
repositories differed materially in purpose and maturity, yet the same
orientation job recurred: establish practical value and current state at first
receipt, route repeat use to the nearest owner, and let live work and machine
records carry re-entry.

The audit found several decision-changing forms of strain: release tags had
advanced beyond prose carriers; accepted families were absent from mutable
catalogs; integration branches contained useful collaboration assets that the
default release line had not accepted; snapshot READMEs could look like living
owners; long roots placed detailed provenance or capability inventories before
the strongest usable result; and nested routes lacked a verification or return
path. One broken fragment supplied a small concrete instance of the same graph
problem.

## Disposition

`repository-orientation-stewardship` receives `create_now`. The job is distinct
from current owners:

- `repository-reentry` establishes current truth for a collaboration cycle;
- `source-authority-mapping` resolves semantic ownership and projection;
- `supportive-change-writing` shapes the prose register; and
- `contextual-jargon-scan` decides whether local shorthand transfers.

The new contract composes those inputs into one repository-wide README graph
with first-receipt, repeat-use, re-entry, snapshot, and machine-companion
boundaries. The human approved promotion and an active implementation wave
supplies its first natural receiving use. The new `.agents/skills/README.md`
also answers a present navigation need: the active contract count has outgrown
a bare directory listing while a separate router skill would add no distinct
result.

## Evidence boundary

The seven-repository audit establishes recurrence and the architecture choice;
it does not establish universal README effectiveness. The first implementation
pull requests provide review evidence for trigger quality, usable headings,
status ownership, and workload. Cold-reader behavior, maintainer correction,
or a materially different repository family can revise or fold the contract.
