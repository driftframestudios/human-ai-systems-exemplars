## Working moment

The Context Canvas link wave needed issue work:registry-reference-coordination to settle receiving routes and a locator-free current tree before issue work:locator-free-public-history could responsibly receive a public-history decision. The route carries a direct human boundary: a clean successor, focused history rewrite, repository re-root, or remote-ancestry deletion begins only after a human selects that action and scope.

Earlier repository work already supplied materially different issue relationships: umbrella coordination, ordered work, an issue contained inside a broader tranche, schema-wave bundles, parallel work, and returns to a coordinating issue. Individual issue bodies could preserve their own outcomes, yet no active skill owned the transition among them.

## Route decision

`collaboration-accounting` selects `create_now`. The job is independently routable: make a small issue family legible as a revisable work route while each issue retains its own outcome, authority, and acceptance boundary. The active work:registry-reference-coordination → current-tree receipt → work:locator-free-public-history handoff supplies immediate receiving use, and explicit human encouragement supports an inexpensive instruction-first attempt.

`issue-chain-stewardship` names the current front, evidenced relations, held conditions, transition receipt, next receiver, and release event. `repository-reentry` still resolves each issue's current truth; `source-authority-mapping` still traces cross-surface artifacts; `planning-inventory` remains a broader billet with its own forge condition.

## First natural use

The Registry link handoff now carries an Issue Chain capsule. Issue work:registry-reference-coordination owns public receiving routes, current-tree replacements, and the private-resolver return. Issue work:locator-free-public-history receives the accepted tree receipt and retains the human-cued history decision. Parallel route families remain visible, and the chain exits when work:locator-free-public-history accepts the handoff or names the exact remaining condition.

This first use declared the release mechanism. The chain is temporary. Ordinary issues and repository history retain the durable record, while any dashboard, score, routing service, history-management system, or source of implementation authority would require its own material receiver.

## First exit observation — 2026-08-25

Issue work:registry-reference-coordination produced the complete current-tree receipt through PR work:context-canvas-current-tree-disposition: 37 visitor-facing Notion identities across 93 occurrences in 31 Context Canvas HTML files, with 30 private working identities resting in the resolver after their useful visitor jobs moved locally. Issue work:locator-free-public-history recorded that handoff and retained the history route as a direct human choice.

This is a successful broad exit. The chain made the preparer, receipt, receiver, and held decision legible, then settled when the receiver could state its exact at-rest condition. Receiver acceptance can therefore mean **prepared and human-held**; it need not imply that the downstream operation has begun. The existing instruction contract and collaboration-account shape carried the observation, so the schema remains unchanged.

## Second natural use — reversible history rehearsal

Issue work:public-baseline-rehearsal forms a contained preparation route after work:locator-free-public-history accepted the scoped Context Canvas HTML receipt. Its repository-wide audit surfaced a previously unowned current-tree prerequisite: 37 other tracked files carrying 89 additional workspace identities, including two hidden skill-reference files, plus 53 links whose old Issue/PR receivers would change under a same-slug successor. Issue work:repository-locator-disposition now owns that source-standing, collaboration-link, and private-resolver return before work:public-baseline-rehearsal completes its cutoff-bound rehearsal across refs, pull refs, Pages, schema receivers, commit metadata, GitHub-native prose, and recovery forms. work:locator-free-public-history retains the human-held route choice and remote-operation cue.

This is a different chain shape from the first use: an accepted receiver can contain a reversible evidence tranche, and that tranche can surface a narrower prerequisite without invalidating the accepted scope. The active route is now `work:repository-locator-disposition → work:public-baseline-rehearsal → work:locator-free-public-history`. The release events are work:repository-locator-disposition's complete current-tree receipt and work:public-baseline-rehearsal's concise disposition packet, rather than a ref change. The existing issue-chain contract describes that relationship cleanly, so this use strengthens the current skill without forming another routing artifact or schema field.

## Transfer boundary

The observed issue families establish local transferability rather than universal project-management guidance. Plain relations such as `prepares`, `blocks`, `receives`, `runs alongside`, `contains`, and `returns to` stay ordinary prose vocabulary. A future repository may use different language while preserving current front, issue-owned contracts, transition evidence, human-held decisions, and release.

## Re-entry

Return when a receiving issue cannot reconstruct why it is current, a meaningful parallel branch disappears from the account, a chain remains active after its receiver accepts the handoff, or a materially different issue family demonstrates a narrower or more useful contract. Fold or retire the skill if ordinary issue links and repository re-entry consistently carry the same result with less attention.
